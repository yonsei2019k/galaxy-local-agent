# 목표 설정
목표를 만들거나 구체화해 달라는 요청에 사용한다. 일상 질문마다 목표 설정을 요구하지 않는다.

원하는 결과를 한 문장으로 적고, 관찰 가능한 성공 기준·대상 범위·필수 제약·다음 행동을 정리한다. 사용자가 수치나 마감일을 주지 않았다면 임의의 수치를 확정하지 않는다. 결과 달성에 꼭 필요한 기준만 물어본다.

이 지침을 읽었다고 목표를 자동 저장하지 않는다. 사용자가 지속할 목표의 저장·추적을 요청하면 현재 대화의 get_goal로 실제 상태를 읽고 create_goal로 초안을 저장한다. 이미 있는 목표는 실제 goalId·expectedUpdatedAt와 기준 ID를 사용해 update_goal로 수정한다. 일반 메모를 지속 목표 대신 만들거나 다른 방의 목표를 가져오지 않는다. 목표가 없는 일회성 요청도 같은 대화에서 바로 계획·조사·실행할 수 있다.

긴 문장의 일부를 바꿀 때는 get_goal의 textField·원문 구간으로 실제 내용을 읽고 textEdits의 관찰한 oldText만 교체해 나머지를 보존한다. 잘린 요약이나 일부 조건만으로 원문 전체·조건 배열을 덮어쓰지 않는다. 읽지 않은 기준은 유지하고 변경된 작업의 이전 완료 근거를 새 작업에 옮기지 않는다. 실제 모델 입력에 전달되지 않은 내용은 읽었다고 하지 않는다.

사용자가 목표 추진을 요청하면 start_goal, 일시정지한 목표를 재개하려면 resume_goal을 쓴다. 현재 구현은 연결된 제한 실행 한 건이며 자동 반복·상시 감시가 아니다. pause_goal·clear_goal은 연결된 작업을 정지한 뒤 상태를 바꾸며 자기 자신을 멈추는 처리가 남아 있으면 PREPARED를 실제 중지 완료라고 바꾸지 않는다. 중지·해제는 이미 수행한 외부 작업의 취소가 아니다.

기한이 있는 목표와 실제 알림 예약은 다르다. 알림을 원하면 해당 도구와 날짜를 확인한다. 목표 저장·대기열 등록·스킬 읽기는 목표 달성의 증거가 아니다. 모델이 기준을 임의로 검증됨·완료로 바꾸지 않는다. 권한·대상 범위·승인·취소와 실제 도구 결과를 따르며, 제공하지 않는 Codex 기능까지 구현됐다고 주장하지 않는다.
