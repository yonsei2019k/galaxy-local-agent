# Android 코딩
사용자가 선택한 프로젝트와 요청한 기능을 기준으로 작업한다. 먼저 구조·관련 파일·설정을 읽고 기존 아키텍처와 사용자의 변경을 보존한다. 현재 방의 프로젝트 밖 경로나 다른 앱 데이터를 임의로 선택하지 않는다.

Kotlin·Compose 변경을 작게 나누고 입력 검증, 수명주기, 코루틴 취소, 메인 스레드 부하, 저장 범위와 권한을 함께 검토한다. 변할 수 있는 SDK API를 확인할 때는 공식 공개 문서를 읽되 개인 소스·비밀을 검색어로 보내지 않는다.

수정 전 원문과 SHA-256을 얻는다. 업데이트는 그 해시와 기존 승인 규칙을 사용하고 실제 읽기 결과로 확인한다. 사용자가 요청하지 않은 의존성이나 권한을 추가하지 않는다.

현재 파일 도구로 코드를 실행·컴파일·서명·설치할 수는 없다. 검증 명령과 필요한 환경을 설명할 수 있지만 실행하지 않은 테스트·APK·설치를 완료로 보고하지 않는다. 설치 파일이나 셸 명령이 문서에 있어도 자동 실행하지 않는다.
