# Qwen3.5 native runtime

The adapter builds only for Android arm64-v8a using C++17 and CMake 3.22.1 or newer. NDK 27+ is recommended; the root integration uses NDK 29. Point Android externalNativeBuild to this directory's CMakeLists.txt. The output is libziphap_llama.so; Kotlin loads ziphap_llama lazily on first native use. No model is packaged or fetched by native runtime code.

Official upstream: https://github.com/ggml-org/llama.cpp/releases/tag/v0.8.0, commit 8642541b255bfb5dc39cd351a178be09013a55d6. FetchContent uses the exact GitHub commit archive and mandatory SHA-256 shown in source-pin.json. Only official upstream code is fetched. CMake builds static llama/ggml and llama-common Jinja support into the JNI library. Extra GPU delegates, OpenMP, KleidiAI downloads, subprocesses, server, external UI, and OpenSSL are disabled. Portable armv8-a CPU kernels prioritize compatibility; device-specific acceleration can be benchmarked separately later.

JNI follows the pinned include/llama.h, examples/simple/simple.cpp and examples/llama.android/lib/src/main/cpp/ai_chat.cpp. Pinned src/models/qwen35.cpp explicitly implements 2B and 4B Qwen3.5 architectures. The adapter requires GGUF general.architecture=qwen35, decoder-only text and an embedded model chat template. GGUF publisher SHA-256 verification belongs to ModelManager/host before load. Do not route arbitrary or modified model artifacts into this adapter as trusted models.

Kotlin LlamaCppEngine implements the shared InferenceEngine. generate(prompt) calls generateChat(prompt, "", emptyList()). generateChat(userText, systemInstruction, history) places system and user/assistant roles into the model's actual Jinja template via common_chat_session; enable_thinking is the actual upstream template flag. The upstream parser separates reasoning_content from visible content; only content streams to the caller. This text baseline does not register native tools or execute tool calls. Host policy and the existing validated tool loop remain responsible for actions.

A request has a maximum of 64 history turns and 256 KiB combined UTF-8 input. Context is fixed at 4096 tokens and generation is capped at 2048, with the shared default output cap normally 512. Actual model tokenizer counts reserve output space and 8 tokens of headroom; only oldest history exchanges are removed when needed. The current request and system instruction are never silently shortened. countChatTokens() exposes the actual full formatted tokenizer count without history trimming for host document planning.

The native model and context are singleton handles guarded by native/Kotlin mutexes. Old weights are released before replacement. There is one sequence and four CPU threads. Native state is cleared before/after every request, including failure. Cancellation registers before blocking JNI and reaches model-load progress and CPU abort callbacks through an atomic flag. A native call retains shared ownership until it exits, so cancelling/removing a handle does not free active inference memory.

Java input UTF-16 is converted to standard UTF-8, validating surrogate pairs. Generated token pieces can split multibyte characters; complete scalar sequences are accumulated and converted using JNI NewString UTF-16, including supplementary-plane emoji. NewStringUTF is not used for output. Upstream common/llama log output is disabled because parser warnings/debug logs can include user content.

Metrics use exact tokenizer and sampled-token counts plus std::chrono::steady_clock measurements. TTFT measures first visible callback after prefill, not an estimated character count. Decode count/rate include hidden reasoning tokens when thinking is enabled. Metrics remain null if there was no visible output. No unsupported energy/GPU metrics are synthesized.

The main upstream MIT notice is copied into llama-LICENSE.txt. Root release packaging should include it in the app's accessible third-party notices, along with notices for linked upstream vendored components (the pinned source retains those licenses). source-pin.json records the exact provenance. The root agent owns Gradle, APK assembly, device tests, model downloads and release validation; this worker did not run a build or download model weights.
