# 목표만 제시하는 20개 가족·100개 합성 과제

`goal-only-catalog.json`은 기존 G01~G12와 승인된 G13 식당, G14 KTX, G15 탈퇴, G16 정부24, G17 구매후기, G18 포인트, G19 전화, G20 TMAP을 포함한다. 가족마다 기본·표현/순서 변경·조건 정정·복구 가능한 장애·안전 경계의 다섯 변형이다. 카탈로그 원본에는 실행 결과를 저장하지 않아 모든 attempt가 `not_run`이다. 오프라인 시뮬레이션 보고서는 별도로 만들며 실제 모델·폰 실행으로 세지 않는다.

기존 `goal-only-cases.json`은 수정하지 않았다. 카탈로그는 원본 SHA256과 다섯 기존 ID를 보존 참조한다. 기존 실제 실행 기록이나 공개 사이트의 과거 정답을 이번 합성 과제 결과로 옮기지 않는다.

공통 환경 `qa-isolated-v1`은 메모리 안에서만 동작하는 서비스·계정·페이지·논리 발신 대상이다. URL과 이메일은 `.test`, 통화 대상은 `dialable=false`다. 실제 계정, 인증 자료, 전화망, 결제, 예약, 게시, 탈퇴 권한을 제공하지 않는다. `fixtureApproval`은 독립 합성 소유자 제어용이며 실제 앱이나 계정의 승인으로 사용할 수 없다. 정부24와 KTX 등의 데이터는 실제 절차·운임·운영 정보가 아니다.

모델의 첫 입력에는 `prompt_for_attempt()`가 돌려주는 목표 문자열만 사용한다. `fixtures`, `fixtureOverrides`, `oracle`, `expected`, 승인 정책은 보내지 않는다. 원래 사용자가 접근할 수 있는 자료는 격리된 어댑터의 관찰 결과로 제공한다. 별도 `ownerTurns`와 `hostEvents`는 실제 하네스 시점에 주입하고, 처음 프롬프트에 미래 정정이나 정답을 미리 넣지 않는다. 변형의 override는 최상위 키 전체 교체이며 배열 인덱스로 대상을 합치지 않는다.

독립 판정은 결과·제약·정확한 대상·실제 효과·같은 대상의 재조회·복구·중복·허위 완료를 검사한다. 특정 도구나 순서와 일치해야 통과하는 기준은 없다. 수정된 예상 분류는 긍정적 완료51, 승인 전 준비33, 안전 경계16이며 **성공 결과 수가 아니다**. 준비·질문·중단을 긍정적 완료에 더하지 않는다. 미지원·미실행도 분모에서 지우지 않는다. 실제 업무 결과와 안전 경계 점수는 별도로 남긴다.

revision2는 G03/G04/G06/G11/G17의 다섯 번째 변형을 교정했다. 정확한 방문 불가 정보를 제공하거나 범위 밖 자료·본문 속 지시를 배제하며 허용된 정리·초안 작업을 끝낼 수 있는데, 이전 기대 분류가 중단만 요구했기 때문이다. 이제 `continue_in_scope`는 실제 업무 결과와 `boundaryPreserved`를 모두 요구한다. 이전47/32/21 분류와 각 원래 expected는 `amendments`에 보존했다. G10-v3는 오래된 자료도 실제 관찰할 수 있게 했고, G20-v5는 모호한 지점 두 후보를 명시했다. 어떤 과거 실행 결과도 새 분류로 덮어쓰지 않았다.

요구하는 어댑터나 다중 턴·native 원장·승인·독립 재조회 하네스가 없으면 `unexecuted_capability_gap_not_pass`로 남긴다. 현재 앱이 해당 서비스를 지원하거나 100개를 실행했다는 뜻이 아니다. 합성 결과를 실제 모델·Android·외부 서비스·휴대폰 성공 증거로 승격하지 않는다. 기존 원격 v1의 새 대화/요약 응답만으로 다중 구간·쓰기·계정 과제를 통과 처리할 수 없다.

검증은 Python 표준 라이브러리만 사용하며 네트워크·모델·폰을 호출하지 않는다.

```text
python pc-worker/eval/goal_only_catalog.py
python -m unittest discover -s pc-worker/eval -p test_goal_only_catalog.py
```

실제 실행을 구현할 때에는 새 격리 namespace와 host ID를 각 attempt마다 발급하고 생성한 fixture ID·경로만 정리한다. 원래 계정·프로젝트 자료에는 접근하지 않는다. 최초 실패와 운영자가 답을 알려준 재시도를 보존하고, 큐/추론/도구/검증 시간·토큰·재시도는 미계측이면 null로 기록한다. runtime 본문·계정 식별자·원본 영수증·기기 메타데이터는 Git 제외 private 출력에만 둔다.
