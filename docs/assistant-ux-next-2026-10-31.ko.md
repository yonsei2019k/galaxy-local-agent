# 비서 UX 후속 작업과 실행 경계

사용자는 진행 중인 이미지 생성 보존과 다른 개발 채팅 접촉 금지를 유지한 채 설치 대기 시간을 활용한 추가 준비를 요청했다. 이 문서는 구현과 후속 설계를 구분한다.

## 1026에 통합하는 범위

- 답변에 있는 파일/이미지 여러 개를 중복 없이 순서대로 표시한다. UUID/확장자를 제한하고 최대16개로 메모리를 제한한다. 존재하지 않는 결과는 조용히 숨기지 않고 상태를 표시한다. 파일의 열기(ACTION_VIEW), 공유(ACTION_SEND), 위치 선택 저장은 사용자 클릭으로만 수행하며 저장 뒤 해시 재조회를 유지한다. 글자 크기가 커져도 버튼을 다음 줄에 배치한다.
- 이미지 시리즈를 이름별 최대12개 보관한다. 같은 이름은 갱신하며 가득 차면 새 저장을 거부하고 자동으로 기존 항목을 버리지 않는다. 선택 불러오기와 확인 후 조건 삭제를 제공한다. 암호화 원자 파일 한 개에 저장하며 기존 단일 recipe는 읽기 호환 후 명시 저장 시 새 형식으로 변환한다. 기준 사진의 SHA/내부 복사/출력과 분리한 보존 계약을 유지한다. 프리셋 삭제는 원본/기준 사진/생성 결과를 삭제하지 않는다.
- 최신1025 앱/테스트/APK 증거와 진행 중인 설치 대기를 보존한다. 1026 호스트 검증은 별도 증거다. 실제1026 설치/기기 검사 전 동작 검증 완료로 표시하지 않는다.

## 다음 구현 전에 필요한 조건

### 범용 실패 단계 재개

텍스트 이어쓰기는 이미 지원하지만 외부 행동 재개와 다르다. 도구 호출 직전의 실행 의도와 식별자, 성공/실패/미확인 결과, 검증 영수증을 요청별로 영속화해야 한다. 프로세스가 종료되면 미확인 변경은 조회·대조부터 수행하고 확인되지 않은 발송·등록을 자동 재전송하지 않는다. 기존 프로젝트/분기/자료 범위/권한/취소/실행 예산을 유지한다. 이전 모델의 계획을 새 사용자 지시나 새 권한으로 올리지 않는다.

필수 회귀: 호출 전 중단, 실제 변경 후 영수증 저장 전 중단, 조회 결과 불일치, 중복 요청, 사용자의 새 수정, 방/프로젝트 변경, 목표 버전 변경, 연결 해제, 이미 취소한 작업, 기존 읽기 전용 큐. 원래 작업의 효과를 확인할 수 없는 도구에는 범용 재개 버튼을 제공하지 않는다.

### 변경 되돌리기

원본 snapshot과 현재 버전 비교가 가능한 문서/파일부터 지원한다. 사용자나 다른 작업이 이후 수정한 파일은 덮어쓰지 않는다. 이미 보낸 메일/메신저 메시지를 파일처럼 되돌릴 수 있다고 표시하지 않는다. 복구 가능한 대상·범위·미복구 대상을 미리 보여준다.

### 문맥 확인과 복귀 요약

현재 요청에 실제 전달한 자료/기억/모델/PC 사용의 영수증을 기준으로 표시한다. 자료 제외는 다음 생성 입력에서 실제로 빠지는지 검증하며 이미 끝난 외부 행동을 소급 취소하지 않는다. 복귀 요약은 마지막 확인 cursor 이후 요청별 실행 결과만 사용한다. 과거 결과를 새 알림으로 반복하지 않고 읽음 상태와 원래 방으로 이동을 연결한다.

## 검증 구분

호스트 테스트/서명 APK/실제 설치 SHA/기기 UI/실제 로컬 모델/사진 동일성은 별도 상태로 남긴다. 공개 합성 자료만 테스트에 사용하며 원래 이미지 생성이나 개인 통화/대화의 분석을 재개하지 않는다. 새로운 범용 재개·복구 기능은 이 설계만으로 구현됐다고 하지 않는다.
