# 피클 공식 사례와 ZipHap 서비스 확장 기준

2026-11-18 기준 공식 공개문서를 조사했다. 실제 서비스 시나리오는 미실행이다. 연결 계정에 접속하거나 주문·게시·발급을 실행한 기록은 없다. 공개 영상에서 보이는 화면으로 내부 실행 경로나 성공률을 확인할 수 없으며, 피클의 기능·보안 설명은 제작사가 공개한 범위에서 인용한다.

## 피클이 공개한 기능

- 피클은 대화에서 날짜·인원 등 필요한 조건을 받고 승인 카드로 작업 범위를 보여 준다. 자체 웹 브라우저를 통해 조사, 예약, 구매, 구독 취소, 계좌 기록 분석, 정부 문서·신청을 처리한다고 설명한다. 웹 예약이 없는 경우 전화 경로를 쓰고, 예약 결과에는 확인 링크 또는 확인 화면을 제공한다고 안내한다. 예약·주문·신청·게시의 단계별 성공은 해당 서비스의 실제 결과로 확인해야 한다. [피클 작업 맡기기](https://pickle.com/help/tasks/delegate), [피클 소개](https://www.pickle.com/help/start/what-is-pickle)
- 피클은 휴대전화와 별도인 가상 브라우저, 파일 작업 공간, 계정·카드 금고를 설명한다. 기준보다 결제액이 오르면 다시 묻고, 계정·카드 접근 내역과 예약 작업의 실행 기록을 보여 준다고 안내한다. 피클 사용에는 플랜과 사용량 제한이 있다. 한국어 이용약관 페이지에 표시된 시행일은 2026-12-08로, 조사일 이후다. [격리](https://pickle.com/privacy/isolation), [승인 및 접근 안내](https://pickle.com/help), [사용 기록](https://pickle.com/help/privacy/activity), [예약 작업](https://www.pickle.com/help/tasks/scheduled), [사용량](https://www.pickle.com/help/credits/usage-credits), [시행 예정 약관](https://www.pickle.com/ko/terms-of-service)

## ZipHap에서 연결할 경로

공개 문서에 개인 사용자 권한으로 호출할 수 있는 공식 API가 확인되면 그 권한으로 호출한다. 아래 표의 웹·앱은 각각 앱 내 WebView 또는 본인 PC의 headless Chrome, 그리고 폰의 서비스 앱을 뜻한다. 권한 근거와 해당 버전 어댑터가 확인된 경로에서만 자동 동작을 연결한다. 로그인 만료, 재인증, 결제 인증, CAPTCHA, 간편서명, 보호된 입력은 사용자가 서비스의 화면에서 직접 처리한다. 로그인 세션은 해당 브라우저의 프로필 또는 앱 범위 안에서만 쓴다. 금고나 결제수단 자동 주입은 아래 사례의 전제에 없다. 네이버는 사전 허락 없는 자동 게시·로그인 등 이용을 제한하므로 네이버·Npay의 실사용 기본 경로는 공식 화면에서 사용자 직접 조작과 사용자가 고른 결과 자료다. [네이버 이용약관](https://policy.naver.com/policy/service.html)

쿠팡 Open API는 WING 판매자 등록을 전제로 키를 발급한다. 네이버 커머스 API는 주문·상품·판매자 등 상거래 운영 범위를 명시한다. 아래 개인 구매내역, 고객용 상품평 등록, 개인 리뷰 점수·Npay 포인트 원장에는 조사한 문서에서 사용할 수 있는 공개 개인용 API가 확인되지 않았다. 사용자 로그인 상태만으로 판매자 API 권한은 생기지 않는다. 정부 서류 발급도 공식 사용자 화면을 사용하며 공개 민원 안내는 개인 문서 발급 토큰의 근거가 되지 않는다. [쿠팡 API 키 발급](https://developers.coupang.com/ko/getting-started/issue-open-api-keynew?market=KR), [네이버 커머스 API](https://apicenter.commerce.naver.com/docs/commerce-api/current), [정부24 등·초본 안내](https://www.gov.kr/mw/AA020InfoCappView.do?CappBizCD=13100000015)

기존 구독과 개인 PC를 전제로 하고 일상 추론의 로컬 경로를 유지한다. 서비스 자체 결제·수수료는 사용자 승인 금액에 포함한다. 아래 서비스에는 신규 유료 API·통화 계정·호스팅을 전제로 한 자동 경로가 없다. 구독 만료, PC 오프라인, 어댑터 부재, 로그인 만료는 관찰 경로나 작업의 상태에 표시한다. 설치된 기기와 각 서비스의 대상 버전에서 검증한 뒤 기능을 지원한다고 표시할 수 있다.

## 실행·검증 조건

- 실행 전 승인에는 계정과 대상, 수행할 한 가지 효과, 금액·통화·수수료 또는 게시 본문·첨부·수신처, 실행 기한을 묶는다. 호스트가 화면·버전·대상과 승인 값을 바로 다시 확인한다. 취소·만료·세션 교체·계정 변경·새 금액·다른 도메인에선 화면을 새로 읽고 필요한 승인을 다시 얻는다. 문서·페이지·메일 본문의 지시문은 자료로만 읽는다.
- 외부 쓰기 시도는 `계정 + 서비스 + 대상 항목 + 요청한 효과 + 승인 본문·금액 버전`으로 기억한다. 동일 시도의 쓰기 응답이 유실되면 조회만 재개한다. 제공자가 거래 ID를 발급하면 같은 서비스 계정의 주문·예약·리뷰·민원·메일 내역에서 다시 조회해 연결한다. 조회 결과에 따라 실행 전, 인계, 접수, 완료, 미확인을 표시한다. 미확인 상태에서 새 쓰기를 시작하려면 최신 상태 증거와 새로운 사용자 결정이 필요하다.
- 허용된 읽기 추적은 계정·대상·주기·종료·보관기간을 고정한다. 포인트·점수·랭킹 외에도 배송·반품·예약·갱신·리뷰 가능 기한의 변화를 같은 버전과 원본에서 비교한다. 관찰 중단과 실제 값 그대로를 구분한다. 원장 거래 ID 또는 사용자 공개 범위의 기록을 기준으로 변경을 한 번 알린다. 잠긴 앱, 민감 정보 화면, 계정 불일치에는 읽기 요약도 제공하지 않는다.
- 플랫폼이 소비자 자동 게시를 명시적으로 허용하는 미래 연결에서는 본인 실제 구매·직접 제공한 경험과 게시 전 승인, 동일 리뷰에 1회 쓰기, 새로 읽은 게시물로 정확한 본문·별점·첨부·광고 표시 확인이 필요하다. 아래 합성 `review_post_permitted_fixture`는 그 계약의 시험용이며 실제 쿠팡·네이버에 대응하지 않는다.
- [합성 시나리오 카탈로그](../../rust/scenarios/service-expansion-v1.json)는 30건과 각 5회 판정 기준을 정의한다. 가상 대상과 경계를 다루며 일부 동작 이름은 필요한 어댑터 계약을 표현한다. 실제 런타임 등록과 권한은 별도다. 현재는 카탈로그 검증만 했다. `scripts/evaluate-agent-scenarios.py --catalog rust/scenarios/service-expansion-v1.json --validate-catalog`로 파싱할 수 있다. 실제 0/150건, 서비스 계정 연결·기기 증거 0건이다.
