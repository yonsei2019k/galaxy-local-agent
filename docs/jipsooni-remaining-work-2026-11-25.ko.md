## 어떤 작업을 먼저 넘길지

1. **첫 구현 묶음은 P0-A와 P0-B다.** P0-A는 동일 숙소 가격을 확인하지 못한 실제 사례부터 다시 재현한다. P0-B는 채팅 안 보안 카드와 완료 후 상태 전환을 맡는다. 두 작업의 접점은 날짜·인원·요금과 인증 대기를 같은 작업에 저장하는 지점이다.
2. **두 번째 묶음은 P0-C와 P1-C의 중복 방지다.** 합성 사이트에서 한 번 내보냈는지 확인하고 공식 사이트에서는 허용 범위까지 시험한다. 가상의 견적과 실제 견적, 실제 예약 확인은 별도 기록으로 남긴다.
3. **세 번째 묶음은 P1-A·B·D·E·F다.** 숙소에서 검증된 거래 계약을 쇼핑·예약으로 옮기고, 디자인 마감과 기존 업무 회귀는 공통 영역 충돌을 피해서 검토한다. P2는 실제 사용 결과를 바탕으로 적용 순서를 조정한다.

## 이어받는 사람의 시작점

- 캐노니컬 경로는 `C:\Users\VICTUS\source\galaxy-local-agent`다. 현재 숙소·채팅 기준은 `C:\Users\VICTUS\source\ziphap-claude-elearning`의 `codex/work-history`에 있다. 인계 전 먼저 `git status`와 각 워크트리의 소유 범위를 확인한다.
- [변경 기록](agent-change-log.md)과 [기기 검증](device-validation.md)에서 최신 증거를 확인한다. 원본 실패는 보존하고 재시험을 별도 행으로 기록한다. 이미 통과한 기능을 기준선에 올리고 실패, 미검증, 변경 경로와 복합 시나리오를 우선 확인한다.
- 패키징 대상은 [자동 업데이트 접수 절차](automatic-updates.ko.md)에 따라 주 작업방과 캐노니컬 체크아웃의 비공개 인계 폴더에 보고한다. 기능, 실제 시험 범위, 브랜치·커밋, 앱·PC 버전, 패키지 해시와 설치 여부를 함께 남긴다. 한 묶음에서 통합을 끝낸 뒤 서명·설치·실기를 진행한다.
- 집순이 대화가 사용자 진입점이다. 필요한 계정·권한은 기존 흐름에서 확인하고, PC 웹 작업은 전용 헤드리스 브라우저를 쓴다. 본인 인증은 휴대폰에서 처리한다. 예약·결제·전화·외부 발송에 필요한 기존 승인과 완료 확인을 지킨다.
