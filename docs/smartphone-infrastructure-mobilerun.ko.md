# 집합 스마트폰 비서 연동 점검과 구현 계획

기준은 2026년 11월 24일 개인 시험판 0.1.75(2075)의 소스 `a2e4061`이다. 표의 구현은 집순이의 실행 경로가 소스에 있다는 뜻이다. 시험 도구와 화면만 있는 경우에는 별도로 표시했다. 계정의 승인 범위, 실제 작업 결과, 재부팅 후 재개는 실기 결과가 있어야 통과로 기록한다.

| 영역 | 구현되어 있는 것 | 남은 것과 통과 기준 |
|---|---|---|
| 1. 기기 제어와 센서 | `ScreenControl`은 Android 접근성 트리와 현재 화면 참조로 탭·입력·스크롤을 실행하고, 실행 전 화면을 다시 읽는다. 선택적으로 화면의 시각적 단서를 함께 쓴다. `AssistantNotificationListener`는 허용된 알림과 메신저 답장 경로를 연결한다. `ToolExecutor`·`CalendarGateway`에 인텐트·연락처·기기 캘린더, `FileToolOperations`에 선택한 파일 경로가 있다. | 비활성·선택 상태와 앱이 제공한 목록 행 문맥을 읽는 기능을 추가했다. 행 정보를 제공하지 않는 화면의 그룹 판별, 창 전환 직후 화면 선택, 알림 이벤트 장부, 권한을 받은 위치와 지오펜싱은 별도 작업이다. 이번에 알림 카운터가 한도에 도달해도 최근 키를 유지하도록 고쳤다. 재시작을 넘는 이벤트 장부는 남았다. 완주 시험에서 같은 이름의 버튼, 키보드가 떠 있는 창, 알림 중복, 위치 권한 철회를 재현한다. |
| 2. API와 브라우저 | `ConnectionCatalog`·`GoogleConnectionAuth`는 Gmail·Google Calendar·Drive 등 계정 단위 도구를 정의한다. 앱 WebView와 페어링 PC의 전용 헤드리스 브라우저 경로가 있다. Notion·Telegram·Todoist에는 서비스 토큰을 확인하는 실행 경로가 있으며 계정별 실기가 필요하다. | Outlook·Slack·GitHub의 집합 채팅 실행 경로와 범용 MCP 연결은 신규 작업이다. API 응답과 저장된 결과를 같은 계정에서 비교하고, 세션 만료에서 원래 작업으로 이어지는지 검증한다. Codex 데스크톱의 커넥터 권한은 집합 앱의 연동으로 계산하지 않는다. |
| 3. 자격 증명과 사용자 인계 | 앱 및 전용 PC 브라우저에 휴대폰 보안 입력 경로가 있다. `BrowserAuthContinuation`으로 로그인 확인 뒤 기존 작업에 연결한다. `ConnectionStore`는 서비스 토큰과 계정 정보를 Android Keystore 키로 암호화해 보존한다. | 웹 비밀번호의 선택적 저장·재사용·폐기 정책, 세션 만료·mOTP·생체인증·CAPTCHA 이후 같은 작업 재개 실기 검증이 남았다. 사용자에게 폰에서 인증을 요청하고, 사이트의 성공 신호를 확인해 같은 작업을 한 번만 재개한다. 브라우저와 작업별로 세션과 비밀값의 수명을 구분한다. |
| 4. 기억과 체크포인트 | `AnalysisMemoryIndex`·`AnalysisMemoryWorker`가 저장된 분석을 색인하고, `GoalProgressStore`와 실행 저널이 목표 상태 및 근거를 보존한다. | 교차 업무 검색과 출처 충돌 정리는 품질 검증이 필요하다. 동일한 의미의 자료를 두 번 가져와도 결과가 중복되지 않고, 원문 삭제·권한 철회 후 색인에서도 조회되지 않아야 한다. 재개 시 목표와 승인 범위가 재시작 전과 같아야 한다. |
| 5. 백그라운드와 이벤트 | `ScheduledReadWork`, `GoalWaitWork`, `ReminderScheduler`에 WorkManager·AlarmManager 경로가 있다. 지속 영상·특정 시각·소유자 인증 대기에서 조건별 재개를 지원한다. 브리핑 모듈과 페어링 PC 작업기 경로가 있다. | 폰과 PC에서 공통으로 쓰는 이벤트 수신 확인·취소·재실행 상태를 정리한다. Doze, 통신 단절, 재부팅, PC 작업기 재시작과 동시 취소에서 한 번만 실행되는지 확인한다. 답장 감시는 원본 알림 또는 메일 스레드에 연결해 중복을 막는다. |
| 6. 승인 | `ActionApprovalDialog`, 계정별 승인 세션, Gmail 발송 계약과 화면 실행 전 검증이 있다. Gmail 전송 도구는 발신·수신·본문에 발송 승인을 묶는다. 저위험 읽기·탐색은 기존 권한 안에서 실행한다. | API·앱 화면·웹의 동일한 위험 행동에 일관된 결과가 필요하다. 결제·전송·전화·삭제의 승인 요청과 실제 실행을 계정·대상·내용·작업 범위에 묶고, 승인 뒤 바뀐 화면·대상·금액에서 기존 승인이 무효가 되는지 합성 서비스에서 테스트한다. 채팅 내 카드 연결도 실기에서 확인한다. |
| 7. 결과 검증과 복구 | 기기 캘린더 저장 후 조회, Gmail 보낸편지함 원문 대조, 화면 재관찰, Rust 실행 저널, 목표의 단계별 근거가 있다. | 범용 예약·결제·발송 영수증 재조회, 세션 만료·타임아웃 복구의 동일한 기준이 남았다. 사이트가 성공을 반환하기 직전 프로세스를 종료하고, 재실행 때 기존 영수증을 조회해 중복 실행 0건을 확인한다. 결과가 불명확하면 채팅에 확인한 사실과 다음 확인 시점을 보여준다. |

## DroidRun 소스 비교

- [Mobilerun 프레임워크](https://github.com/droidrun/mobilerun/tree/e34004270a9d7b68824b94a3a5ba6698cefea69d)는 MIT다. `executor_agent.py`는 최근 행동·결과·오류 및 최신 기기 상태를 판단에 함께 사용한다. 집합의 도구 실행 저널과 작업 카드는 이미 결과를 보존한다. 확장할 때는 전체 화면 로그 대신 현재 목표에 필요한 요약과 최신 관측만 재사용한다.
- [Mobilerun Portal](https://github.com/droidrun/mobilerun-portal/tree/49d92110ed9faeaad4c8f65b681c4a3012b1de25)은 AGPL이다. `AccessibilityTreeBuilder.kt`와 `AccessibilityRootResolver.kt`의 계층·상태·창 경계 개념을 검토했다. 집합의 기존 접근성 서비스와 Rust 화면 증거에 독립 구현을 붙였다. 목록 행 번호와 보이는 컨테이너 이름을 결합했다. 다음 작업은 행 메타데이터가 없는 화면의 구분과 전환 뒤 관측 안정화다.
- [Portal 로컬 API](https://github.com/droidrun/mobilerun-portal/blob/49d92110ed9faeaad4c8f65b681c4a3012b1de25/docs/local-api.md)의 전송 구조는 별도의 로컬·역방향 제어 통로를 가정한다. 집합은 기존 페어링·권한·감사 흐름을 유지하고, Android에서 필요한 관측만 범위를 확인해 반환한다. 이 변경에 복사한 업스트림 코드는 없다.
- [Android 15 알림 보안](https://developer.android.com/about/versions/15/behavior-changes-all#otp-redaction)은 신뢰되지 않은 알림 리스너에 OTP 본문을 가린다. 인증번호가 필요한 작업은 휴대폰의 사용자 인계 경로에서 이어간다.

## 구현 순서와 완료 조건

1. **기기 관측과 승인 회귀.** 사용 가능 여부와 선택 상태를 관측에 묶은 첫 패치를 검증한다. 행 메타데이터가 있는 화면과 없는 화면을 구분해, WebView·Chrome·네이티브 앱에서 같은 라벨이 여러 개일 때 정확한 하나만 누르는지 확인한다. 화면이 바뀌었거나 비활성인 경우 실행 횟수는 0건이어야 한다.
2. **계정 연결과 복구를 한 흐름으로 시험.** Gmail·Calendar를 먼저 실기에서 시험한다. 휴대폰에서 승인하고, 의도한 계정·대상에서 실제 데이터를 조회하고, 초안을 다시 읽고, 합성 계정에서 발송을 확인한다. 동시에 연결 인터페이스를 재사용해 Outlook부터 추가하고, Slack·GitHub는 읽기부터 검증하며, Notion은 기존 정의와 실행을 대조한다.
3. **장시간 작업과 백그라운드 재개.** 폰 인증→브라우저 재개→동영상 종료 대기→다음 단계→최종 결과 확인 순서로 합성 사이트를 먼저 돌린다. 네트워크 해제, 세션 만료, 재부팅, 취소를 각각 삽입한다. 실제 사이트에서는 인증과 재개, 과목별 상태·파일이 채팅의 같은 작업에 남는지 확인한다.
4. **알림과 위치·파일.** 허용한 앱별 이벤트를 동일 키·같은 회차로 중복 제거하고, 이벤트마다 실행 범위와 종료 조건을 기록한다. 위치는 사용자가 설정한 구역만 등록하고 철회 시 제거한다. 파일은 Android 선택기로 부여한 범위 안에서 미리보기·저장 후 조회를 확인한다.
5. **범용 완료 근거와 기억.** API 영수증, 새 화면 또는 실제 파일을 목표별 근거로 연결한다. 마지막에 성공을 알리기 전 반드시 조회한다. 업무 기억은 출처를 유지하며 검색할 때 관련 결과만 가져오고 권한 철회와 삭제를 반영한다. 성공·확인 대기·복구 불가를 구분하는 채팅 기록과 복합 실기 결과를 배포 판단에 사용한다.
