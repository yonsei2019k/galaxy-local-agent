# 20개 시나리오 평가와1052

실제 PC 로컬 모델과 합성 도구 결과를 연결해 요청 해석→도구 선택→core 실행 전 검사→결과 관찰→최종 답변을 평가했다. 개인 자료 조회나 실제 문자·메일 발송은 하지 않았다.98개 등록 정의에서 설명 공백을 검사했고, 기존 빈 핵심 설명21개를 채웠다. 해석 단계에는 스킬 조회2개를 제외한96개 기능을 제공했다.

## 증거 범위

- 기준1051 프로필20건의 자동 검사 통과는13건이다. 오케스트레이터가 답변·실행 근거를 검토하면12건이다. 전사 전체를 읽고 바로 할 일을 추출한 합리적 대안1건을 인정했고, 없는 기능을 나중에 실행해줄 것처럼 답한2건을 실패로 정정했다. 원본 자동 점수와 transcript는 보존했다.
- 합성 완료5건, 사용자 확인 대기7건이다. 확인 대기를 실제 발송·일정 저장·알람 설정 완료로 세지 않는다. 미지원 기능의 올바른 고지도 그 기능의 실행 성공이 아니다.
- 모델은 기존 `pc-text`, 문맥8192, 출력512, thinking 요청false이며 모델/코드/카탈로그/과제 해시를 ignored 결과 manifest에 남겼다. 시각은 재현용2026-11-14 10:00 KST 합성값이다. 단일 시행이라 통계적 일반 정확도나 모델 우열은 주장하지 않는다.
- 제품의 ModelDecisionContract, ToolRegistry, SemanticRequestPlanning, TaskHarness를 JVM bridge로 직접 호출한다. 요청 해석은 실제 지침/스키마를 사용한 구조화 프로필이다. Android coordinator의 토큰 예산·구조화 토큰 계산 실패 시 폴백·권한/취소·외부 서비스·전체 후속 검토/긴 구간 실행은 이 평가로 검증되지 않는다.
- 처음 만든 평가기의 인코딩/구조화 액션/의미 계획 문맥 누락을 수정하기 전 예비 결과는 기준20건과 섞지 않는다. PC_BUSY는 미평가이며 모델 실패 점수에 넣지 않는다.
- 보완1052로 선택8건을 다시 실행했다(자동5/8, 가격 감시 오탐 정정 시4/8). 이후 설명의 첫 문장만 남겨 경계 문장이 사라지는 문제를 수정해3건을 추가 검사했다(자동1/3). 이 부분 재검사를 합쳐 최종 APK의 전체20건 성공률로 제시하지 않는다. 미지원 기능은 실제 실행 성공이 아니며 자동 문구 검사에 통과해도 오케스트레이터의 검토가 필요하다.

## 실제 휴대폰과 Tailscale

1052를 데이터 삭제 없이 설치하고 signed main/test APK와 실제 base APK SHA를 독립 대조했다. Core660/app581=1241 JVM, 릴리스 lint 오류0/경고137/hint1, release/test 조립·서명을 확인했다. 최종 합성 지침은 기존900자 예산을 유지하며811자로 줄였고, 검증 한도를 늘리지 않았다.

첫1051 폰 검사는 OVERLAY_NOT_ADVERTISED로 실패했다. Windows 호스트 이름의 DNS 열거에 Tailscale 주소가 빠진 상태였다. 공식 설치 CLI의 자기 IPv4 조회를2초로 제한하고 성공60초/실패5초 캐시하는 fallback을 준비해6회귀를 통과했다. 평가 종료·유휴·모델 정리 확인 후 작업기 코드만 백업/배포/재시작했다. 토큰·인증서·모델·VPN·방화벽 설정은 바꾸지 않았다.

실제 폰의 원래 pinned transport로 overlay 주소에 직접 요청해 VPN 존재·동일 페어링 서버·인증서 고정·인증 응답을 확인했다.1051/초기1052/최종1052에서190/276/136ms로 통과했으며 LAN 폴백을 허용하지 않았다. 시간은 endpoint 정보·health 검사를 포함한다. 외부 Wi-Fi→셀룰러 전환이나 외부 위치에서의 장시간 추론 증거는 아니다.
