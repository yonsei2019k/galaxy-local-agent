# 수신자 선택과 실행 완료 근거: 1059 통합 검증 완료

## 수정한 경계

- 문자 수신 번호는 현재 요청의 명시 번호나 같은 요청에서 실제 조회한 연락처에서 확인해야 한다. 연락처 조회는 표시 limit와 별도로 최대101개를 검사해 첫 항목만 보여준 것을 유일한 대상으로 오해하지 않게 한다. 숫자 서식 차이를 정규화하고, 같은 요청에서 나중에 좁힌 조회로 앞서 확인한 복수 후보를 지우지 않는다. 불완전한 조회 결과는 임의 선택으로 승인할 수 없다.
- 복수 후보는 기본 선택 없는 확인 화면에서 이름·번호·문자 본문을 확인한다. 모델이 첫 번호를 요청했더라도 사용자가 선택한 실제 번호를 실행·기록한다. 선택은 요청과 본문에 한정하며 재사용할 수 없다. 취소하면 문자 앱을 열지 않는다. 새로운 모드나 자연어 키워드별 의도 분기는 추가하지 않았다.
- 명시하지 않은 좌표를 모델이 만들어 `open_tmap_destination`을 실행하는 것을 막는다. 이름 검색과 실제 좌표 전달을 구분한다. 이 제한은 현재 사용자 원문의 좌표 값 근거이며, 공개 검색 결과에서 임의의 좌표를 추출해 승인하는 구현은 아니다.
- 메모·리마인더·연락처·시각·문자/메일/일정 초안·알람·소비자 앱 열기 등 관리 대상 작업의 결과는 호스트가 관찰한 결과로 표시한다. 메모 본문은 저장·재조회된 canonical 값이다. 실행 없이 모델이 만든 완료 문장은 먼저 표시하거나 대화 본문에 저장하지 않는다. 일반 대화와 검증된 조사 장문 경로를 유지한다.
- Android Intent 전달은 실제 화면 표시·저장·발송·길 안내 시작의 증거가 아니다. 요청 전달 후에는 외부 확인 대기로 일시 정지한다. 미확인/실패 결과와 형식 검증 실패도 완료 상태로 닫지 않는다. 사용자 확인 후 실제 실행 직전 대화 분기·프로젝트 버전을 재검사한다.
- 검증된 연락처 조회 뒤 원래 요청의 남은 문자 준비 단계를 모델이 다시 검토할 수 있다. 처음 캡처한 허용 도구에 한정한 후보이며 실행 권한은 아니다. 모델의 실제 선택과 기존 승인·수신자 확인이 필요하다. 연락처 목록만 요청한 경우 문자를 준비하지 않아야 하며, 비활성·읽기 전용 범위를 우회할 수 없다.

이는 모델의 모든 문장이나98개 도구의 의미 정확도를 보증하는 기능이 아니다. 특히 메모 원문의 참조 선택, 요청한 제목/본문의 해석, 일반 분석·조사 답변의 사실 정확도와 미지원 기능은 별도 평가 대상이다. 등록된 도구를 실제로 선택한 뒤 대상·승인·근거를 검사하며, 실행하지 않은 일을 고정 답변으로 완료 처리하는 방식이 아니다.

## 검사 방식과 중간 실패

- JVM: 대상 미관찰/중복/서식 차이/불완전 조회/선택 재사용/다른 본문 재사용과 실제 결과 없는 완료 표시를 회귀 검사한다.
- 실제 Android 화면: 생산 코드의 확인 화면에서 기본 선택 없음, 비활성 버튼의 실제 터치 무효, 두 번째 번호 선택 후 확인을 검사한다.
- 모의 추론 반복: 실제 휴대폰의 coordinator·암호화 Room·승인·Intent 경계를 실행하며 추론 응답과 연락처 자료는 합성이다. 임의 첫 번호 선택, 선택 취소, 실행 없는 완료 문장, 저장 후 본문을 바꾼 완료 문장, 권한 실패 주입을 각각2회 검사한다.
- 실제 로컬 모델 반복: 휴대폰의 실제 coordinator와 인증된 PC 로컬 추론, 테스트 전용 실제 ContactsProvider 자료, 실제 암호화 메모 저장, 기기 시각 조회를 사용한다. 실제 SMS는 발송하지 않는다. 명시한 가짜 번호의 작성 요청만 Android에 전달하고, 화면 표시나 전송 완료로 채점하지 않는다. 모델이 추가 질문을 선택하면 안전한 일시정지로 구분한다.
- QA 프로젝트·대화·메모·연락처만 생성·정리한다. 소유자 연락처 조회는 허용하지 않는 시험 어댑터를 사용한다. 실제 모델 반복에서는 연락처 생성·정리 구간에만 instrumentation의 일시적인 WRITE_CONTACTS shell identity를 쓰고, 모든 추론·네트워크·Keystore 작업은 일반 앱 권한으로 수행한다. 실제 계정 메일·소유자 일정/자료 삭제는 검사하지 않는다. 다른 SMS 앱의 미전송 초안 제거는 검증하지 않았다. 원문·기기 로그·진단은 ignored `.local`에만 보관한다.

1055 첫 검사는 버튼이 아닌 상위 accessibility 노드를 읽은 화면 검사와 모의 엔진의 구조화 토큰 계수 누락 때문에 실패했다. 검증기를 수정했고, 같은 생산 UI는 Compose 검사에서 통과했다. 수정된 모의 반복10회는8통과/2실패였다. 실패2회는 사용자 선택 번호로 작성 요청을 전달한 뒤 루프가 다시 시도하던 실제 문제를 드러냈다.1056은 PREPARED 결과에서 즉시 외부 확인 대기로 멈추도록 수정했다. 실패 기록은 별도 로컬 파일로 보존한다.
