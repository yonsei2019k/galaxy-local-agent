# 대화 안에서 계획·목표·스킬·실행을 이어가는 비서

### 2026-11-22 사무실 기본 채팅과 직원방

일반 진입에서 사무실을 연다. 직원방에서는 해당 직원에게 전달된 일과 실제 진행·대기·검토 이력을 보고, 같은 입력창에서 직원에게 직접 요청할 수 있다. 기존 기록과 협력사 핫라인은 기존 저장·연결 경로로 연다. 새 업무는 방 선택을 요구하지 않으며, 직원방과 프로젝트 자료의 실제 바인딩은 기존 실행 기록을 따른다.

비어 있는 사무실에는 바로 닫을 수 있는 첫 안내를 보여준다. 전화·컴퓨터·계정 전부를 먼저 연결하도록 요구하지 않는다. 휴대폰 일정 읽기 허용 버튼은 Android의 읽기 권한만 요청한다. 앱과 컴퓨터 연결 및 개인정보 버튼은 현재 저장소와 OS 설정을 사용하는 관리 화면으로 간다. 앱은 안내를 닫거나 첫 메시지를 보낼 때 이를 저장한다.

기능 목록은 장치가 보고한 현재 권한·설치·연결 상태를 반영하고, 대화 예시는 편집 가능한 초안으로만 전달한다. 상태 표시는 사용 가능 조건의 근거이며 실제 처리 영수증은 실행 후 따로 확인한다.

### 2026-11-19 맥락 효율 설계 기준 (v1 부분 적용, 장기 메모리 설계 미구현)

현재 설치2018 context v1은 최근 메시지 최대8개(왕복8회가 아님), 메시지당1500 UTF-16단위, 이전 요청3000/목표1500단위, JSON 전체12000 UTF-8바이트다. 긴 글은 앞뒤 원문 발췌와 생략 표시를 사용하며 의미 요약은 아니다. 초기 구현에서 긴 이전 작업이 최근 대화를 밀어내던 문제는 최신 적격 대화 우선 배정으로 수정했다. 순수 헬퍼20개와 실제 두 턴 회상1건은 검증됐으나, 이 결과를 장기 맥락 이해나 전체 토큰 절감으로 확대하지 않는다. 아래 작업 메모리·검색·의미 압축 설계는 별도 미구현 범위다.

새 기본은 `현재 요청 원문 + 검증된 작업 상태 + 최신 정정 원문 + 필요한 과거 근거`다. 현재 요청/정정은 요약으로 대체하지 않는다. 과거 대화는 원본을 암호화 저장하고 별도의 작은 작업 메모리와 원문 참조를 유지한다. 메모리에는 목표, 정확한 대상 식별자/버전, 포함·제외 조건, 최신 결정, 실제 검증된 결과, 미확인 효과, 중단 이유와 다음 단계를 출처와 함께 둔다. 일회성 요청을 새 영속 목표로 자동 등록하지 않는다. 대상·금액·날짜·계정·승인·불확실성은 산문 요약의 추정으로 채우지 않는다. 정보가 부족하면 원문을 다시 읽고, 여전히 애매하면 질문한다. 기억은 권한이나 완료 증거를 만들지 않는다.

추가 메모리 입력 예산의 초기 목표: 독립 단순 요청0~400토큰, 보통 연속 대화600~1200, 여러 단계 재개1200~2400, 복잡한 비교/조사 최대4000. 현재 사용자 요청, 고정 지침, 도구 정의/결과 및 출력·추론은 별도 계측한다. 예산은 모델별 tokenizer 기준이며 바이트/글자 수를 토큰으로 간주하지 않는다. tokenizer가 없으면 보수적 바이트 상한을 병용하고 추정임을 표시한다. 필수 대상·최신 정정·불확실성 때문에 예산을 넘으면 무손실 참조/추가 조회를 사용하고, 필요한 입력까지 확보하지 못한 채 행동하지 않는다. 숫자는 품질 시험 전 초기 기준이지 절감률이나 품질 보증이 아니다.

예산은 과거 작업 상태와 실제 입력 크기로 배분하며 별도 LLM 분류/요약 호출을 매 요청마다 만들지 않는다. 기존 본작업 응답에서 제안된 메모리 변경분만 검증하여 반영하고, 내용 변경이 없으면 갱신하지 않는다. 오래된 산문 압축은 임계치 도달/작업 전환 때만 수행한다. 최신 정정과 짧은 최근 대화 몫을 먼저 보장하고 긴 이전 작업 산문이 이를 모두 밀어내지 못하게 한다. 원문 조회는 현재 허용된 방/분기/프로젝트/외부전송 범위를 지킨다. 원문 미전송 사실을 요약으로 우회하지 않는다. 모든 호출의 전체 입력·출력·조회·압축 비용을 합쳐 비교한다.

고정 지침/도구 정의의 순서와 내용은 가능한 한 안정적으로 유지하고 변하는 작업 상태는 뒤에 배치한다. 제공자가 지원하는 실제 prefix cache 사용량을 계측하되 현재 구독 CLI에서 cache hit나 한도 절감이 보장된다고 주장하지 않는다. 캐시는 재계산을 줄일 수 있지만 필요한 의미 정보를 복원하는 메모리를 대신하지 않는다. 대기 감시에는 모델을 호출하지 않는다.

출시 전 비교 기준(아직 미실행): 최소30개 연속 대화 시나리오×3회, 5~20회 왕복의 정정/대상 변경/중단 재개/오래된 조건 회수/모델·권한 변경을 포함한다. 명시 대상·최신 정정·미확인 효과 유지100%, 맥락 때문에 생긴 오대상/중복 실행/허위 완료0건, 이어가기 정확도95% 이상을 목표로 한다. 동일 모델/도구/요청의 전체 기록 재전송 기준과 비교해 메모리 입력 토큰 중앙값50% 이상 감소를 목표로 하되 전체 작업 토큰과 정확도를 함께 보고한다. 실패·재시도·추가 조회·요약 호출을 비용에서 제외하지 않는다. 실제 단말·현재 구독 실행 증거가 있어야 통과로 기록한다.

### 새 자료 보고와 일정 확인 (1035)

허용 자료의 전체 문맥을 Codex에 전달하는 선택 기능은 일반 로컬 추론과 별개다. LLM 없는 PC 감시가 연결·미분석 자료를 확인하고, 원문 식별자/내용 버전별 새 배치만 분석한다. 앱 저장과 재조회 뒤 완료 처리하며 연결 해제·실패·중지는 완료로 올리지 않는다. 이미 처리한 자료는 관련 문맥으로만 참고할 수 있다. 새 도착 자료가 과거 대기열 때문에 밀리지 않도록 최근 자료부터 확인하고 선택한다.

보고·검토·등록 결과는 폰 알림에서 전용 확인 화면으로 연결하고 자료 연결 화면에서도 열 수 있다. 캘린더 선택은 접힌 메뉴로 두어 여러 계정 목록이 보고를 가리지 않게 한다. 애매한 시각은 날짜/시간 선택기로 확인하며 기존 일정과 충돌·정정·취소·부분 자료는 자동 등록하지 않는다. 이 검토함은 대화의 모드나 새 영속 목표가 아니며, 기존 읽기 전용 큐와 권한을 해제하지 않는다. 모델 데이터는 새 사용자 명령이나 전송 권한이 아니다. 메시지·서류 전송과 초대를 실행하지 않는다.

기본 분석은 최소1시간 간격/하루4회, 배치 최대48건/48KB다.30분 Codex heartbeat는 PAUSED이며 점검·재전달로 모델을 깨우지 않는다. 이미 받은 보고는 PC 없이도 열리지만 새 Codex 분석에는 실행 중인 PC/Codex와 승인된 연결이 필요하다. 문자 본문·알림·통화기록의 실제 확보 범위를 표시하고 전체 대화/메일함/녹음 전사로 승격하지 않는다. 상세 계약은 docs/incremental-personal-briefing.ko.md에 둔다.

### 계획 시간과 후속 검토 한도 (1032)

계획의 모델 준비·입력 확인·생성·전체 시간 한도를 구분한다. 생성 시간 초과에는 현재 요청 원문·명시 목표·원래 권한을 유지하고 선택적 참고 문맥을 줄여 한 번만 새 계획을 만든다. 실패한 일부 JSON을 이어 붙여 실행하지 않으며, 재시도도 끝나지 않으면 요청을 보존해 일시 정지한다. 오래된 대기 요청은 새 권한을 얻지 않는다.

작업 기록은 실제 런타임의 입력 처리 수·샘플 토큰 수·화면 전달 바이트를 보여준다. 내부 사고 원문이나 추정 완료율을 표시하지 않는다. 도구 결과를 본 뒤 모델이 제안한 후속 확인은 원래 요청 범위의 제안이며 새 사용자 발화나 권한이 아니다.

필수 도구의 현재 호스트 근거가 완결된 경우에만, 후속 검토 한도 뒤 새 행동 없이 최종 답변을 작성한다. HOST 출처로 추가 검토 한도와 미검토 범위를 명시하고 모델의 최종 검토 완료로 승격하지 않는다. 부분 출처·실패·필수 결과 누락은 이 경로로 우회하지 않는다. 영속 목표 자체를 자동 완료하지 않는다. 최종 작성 모델이 다시 도구 실행을 요구하면 예산·범위를 다시 검사하고 임의 실행하지 않는다.

첫 표시 전 자원 부족·발열 일시 정지도 작업 행에 paused로 저장한다. 빈 진행 표시용 메시지 행은 생성된 답변이 아니며, 본문이나 이어쓰기 정보가 없는데 이어쓰기 가능을 약속하지 않는다. 실제1032 E4B 합성 검증은 계획·계산·추가 검산·한도 명시 최종 작성 경로까지이며 일반 의미 이해·모든 모델의 성공을 뜻하지 않는다.

사용자 방향 정정:2026-10-31. ZipHap.Agent에서 계획·목표·스킬을 채팅 상단의 작업 종류 탭으로 분류하라는 뜻이 아니다. 사용자는 Codex처럼 한 대화 안에서 필요한 기능을 불러오고, 자료 조사·실행·검증·수정·결과 전달까지 이어가는 제품을 원한다. 이는 화면만 바꾸는 요청보다 넓은 제품 원칙이다.

## 앞으로 지킬 제품 원칙

1. 기본 진입은 같은 채팅 입력창이다. 사용자가 계획·검토·조사·실행 등의 분류를 먼저 골라야 일을 수행할 수 있게 만들지 않는다. 모델이 현재 요청과 최근 대화를 해석하고 필요한 다음 행동을 선택한다. 특정 자연어 어휘나 문장형태에 따라 작업 모드를 강제하는 예외를 추가하지 않는다.
2. 계획은 필요한 작업에서 대화 속에 제시하고, 추가 지시에 따라 같은 맥락에서 고친다. 모든 요청에 계획 양식·전역 분류·다단계 절차를 강제하지 않는다. 계획만 요청한 경우의 의미 해석과 실제 변경 없는 수행은 별도 회귀 사례로 확인한다.
3. 목표는 사용자가 지속할 목표를 명시한 경우에만 현재 대화에 저장한다. 목표의 완료 기준·조건·상태·이어가기·중단은 대화에서 관리한다. 일회성 질문을 자동으로 지속 목표로 만들지 않는다. 저장된 목표나 처리 바이트 수만으로 실제 달성을 선언하지 않는다.
4. 스킬은 작업에 필요할 때 읽는 지침·자료·절차다. 사용자가 라이브러리 탭을 먼저 열어야 실행되는 기능으로 만들지 않는다. 선택적인 찾아보기·관리 진입점은 첨부 메뉴 등에 둘 수 있지만 일반 대화의 전제가 아니다. 실제 실행은 연결된 도구와 저장·검증 경로가 담당한다.
5. 도구 실행, 진행 상황, 필요한 승인, 중간 정정, 결과물과 근거를 같은 대화에 연결한다. 파일 저장·앱 열기·전송 요청·외부 상태 변경·검증 완료를 구분한다. 프로젝트·방·권한·취소·실제 증거 검사는 화면 분류와 독립적으로 유지한다.
6. 기존 저장 요청의 mode/allowTools·읽기 전용·공개 전용 제한을 UI 변경 때문에 조용히 해제하지 않는다. 새 일반 요청의 내부 기본값과 오래된 큐/재개 요청의 이미 캡처된 권한은 구분한다. 등록된 슬래시 명령은 선택적인 대화 명령이며 다음 요청에 숨은 모드를 남기지 않는다.
7. 설정, 프로젝트/대화 탐색, 자료 연결, 모델 선택은 기능 분류 탭과 다르다. 필요한 관리 화면은 유지하며, 자료를 사용하기 위해 모델·프로젝트·권한의 실제 상태를 확인한다.

공식 OpenAI 문서는 스킬을 반복 작업용 지침과 자원으로, MCP를 실제 정보·행동을 제공하는 계층으로 설명한다. 목표는 대화에 지속되는 상태로 설계되어 있다. 이 구조를 제품 판단에 참고한다. 현재 앱의 모델 품질·속도가 Codex와 같다는 근거는 아니다. [스킬과 도구의 역할](https://developers.openai.com/plugins/concepts/skills), [목표의 대화별 상태](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex).

Codex의 공개 자료는 한 세션 안에서 맥락·도구 실행·진행·승인·정정·복구를 연결하는 실행 체계를 강조한다. 이를 기준으로 기능별 실제 차이를 줄인다. 현재의 탭 제거·내장 기능 연동을 모든 Codex 기능의 완성으로 표현하지 않는다. [공개 실행 체계 설명](https://developers.openai.com/blog/codex-as-a-platform), [모바일 작업 흐름](https://developers.openai.com/blog/mastering-codex-remote-for-engineering).

## 긴 목표의 수정과 원문 보존

목표 조회의 짧은 미리보기를 읽었다는 이유로 기존 긴 목표·기준·조건 전체를 교체할 수 없다. 수정은 같은 대화·프로젝트·목표 버전의 실제 원문과, 그 원문이 현재 모델 입력에 전달됐다는 근거를 사용한다. 긴 문장의 일부분은 원문 구간을 읽고 관찰한 유일한 부분만 바꾸어 나머지 내용을 보존한다. 목록의 일부 기준만 읽고 수정할 때 읽지 않은 기준은 유지한다. 새 기준 추가와 기존 내용이 그대로인 요청에 불필요한 전체 읽기를 강제하지 않는다.

이는 자연어 어휘·문장형태에 따른 분류가 아니다. 모델은 요청의 뜻과 수정할 내용을 판단하고, 호스트는 실제 원문 전달·버전·수정 범위를 확인한다. 원문을 아직 읽지 못했다면 먼저 읽고 다시 수정할 수 있도록, 실행 전 거부와 실제 쓰기 뒤 결과 미확인을 구분한다. 현재 실행의 원문 근거를 다른 방·다른 버전·다른 모델 요청의 권한으로 재사용하지 않는다.

## 검증과 전달

신규 일반 입력→필요한 스킬→실제 도구→검증/결과, 계획만 요청 후 같은 대화의 실행 요청, 오래된 읽기 전용 큐/재개의 제한 유지, 대화/프로젝트 변경 중 목표 처리, 일부 기준만 읽고 수정할 때 나머지 기준 보존, 일시정지/해제 중 실제 연결 작업 중지, 사용자/실행 근거를 모델이 임의로 검증됨으로 만들지 못하는지를 검사한다.

소스 반영·JVM·APK·휴대폰 설치·실제 한국어 의미 품질은 각기 다른 증거다. 현재 작업의 정확한 상태와 해시는 agent-change-log/PROJECT_STATE와 로컬 통합 영수증에 갱신한다. 다른 채팅의 장시간 이미지/모델 작업이 휴대폰을 사용하는 동안 설치·재시작·instrumentation을 하지 않는다.

### 휴대폰 카카오톡 연결 (1027 준비)
PC 카카오톡/MCP 상시 실행과 수동 내보내기는 필수 조건에서 제외한다. Android 접근성의 시스템 허용과 앱의 본문 조회 허용을 분리한다. read_kakao_screen은 요청 시 허용 binding을 고정하며 기존 대기 요청은 새 권한을 자동 획득하지 않는다. 지원 버전의 개인 프로필 전경 화면만 읽고 원래 비서 대화로 돌아온다. 편집·비밀번호·보호 화면은 제외한다. 화면 밖/닫힌 방/과거 전체 이력은 현재 미구현이며 수집 완료라고 표시하지 않는다. 카카오 메시지는 지시 권한이 없는 인용 자료다. 읽기 도구에는 입력/전송/삭제 기능이 없다. 카카오의 고정문구 자동 답장을 차단하고 기존 수동 답장도 매번 대상과 본문 확인이 필요하다. 새 소스의 실제 조회·요약과 기기 버전 검증은 APK 설치 후 별도로 기록한다.
