# ZipHap.Agent 미해결 요청 감사 및 재작업 계획

기준일: 2026-10-30. 대상은 독립 Android 프로젝트 `galaxy-local-agent`다. Roblox와 nurse-scheduler는 변경하지 않는다.

사용자가 최근 제외한 제한 해제·무검열 모델 교체 작업은 이 계획의 작업 대상이 아니다. 이미 존재하는 사용자 소유 변경은 일괄 되돌리지 않는다.

## 1. 현재 상태를 판단하는 기준

- **검증됨**: 명시한 빌드·모델·시나리오에서 실제 결과를 확인했다. 다른 APK·모델·전체 기능으로 확대 해석하지 않는다.
- **부분 구현**: 실제 동작하는 범위가 있으나 요청한 사용 흐름 전체는 끝나지 않았다.
- **소스 구현·통합 검증 전**: 코드나 단위 검사는 있으나 최신 APK 설치와 실제 사용 흐름의 증거가 부족하다.
- **미구현/연동 필요**: 실행 가능한 연결이나 필수 인증·런타임이 없다.

현재 확인한 사실:

1. 개인 프로필의 앱은 versionCode1004가 설치되어 있다. 현재 설치 APK의 SHA-256은 `f7630916bccd107f201e7f66d2888c79a0b6fc0c2bf0d08b9ffb6c6adac525f7`이다. 앞서 검증한 다른 개발 APK와 해시가 다르므로 검증 결과를 구분해야 한다.
2. 원격 최신 공개 릴리스는 v0.1.4, 공개 소스 커밋은 `8132b46`이다. 이후 개발 작업이 다수 미커밋 상태로 남아 있다.
3. 현재 단위 결과 파일에는 core301개, app JVM54개 실패 없음이 기록되어 있다. 최근 통합 Validate 실행은 요청 대상 교정 검사 실패로 중단된 기록이 있으며, 그 뒤 생성된 단위 성공 파일만으로 최신 전체 빌드·설치 성공을 주장하지 않는다.
4. 이전 개발 APK에서 로컬 추론, 암호화 기억·프로젝트 파일, 실제 일정 등록/재조회, Office/EML/PDF/TTS/기본 영상, 공개 쇼핑 검색 등의 성공 증거가 있다.
5. 이전 실제 모델→DOCX 도구 검사는 두 번의 모델 시도 모두 실패했다. 새 네이티브 JSON 스키마 경로는 코드로 추가됐으나 실기기 성공 확인과 준비 상태 등록이 남았다.
6. 참조 사진 변환 검사는 사용자 중지 때 프로세스가 종료됐다. 자연 충돌로 단정하거나 통과로 처리하지 않는다.
7. 개인 기억 원문, 계정, 업무 메시지, 기기 식별자, 원시 보고서와 서명 키는 이 공개 문서에 포함하지 않는다.

### 접근 범위의 실제 한계

Android 권한을 허용해도 모든 앱의 비공개 DB, 과거 대화, 보안/업무 프로필이 열리지는 않는다. 앱별 공식 연동, ContentProvider, 알림, 사용자가 가져온 파일, 선택 폴더, 검증한 화면 연동을 조합한다. 각 결과는 실제 읽은 범위를 표시해야 한다. 미연결 데이터를 분석 완료로 표시하지 않는다.

모델 가중치는 고정이다. 이 계획의 상시 학습은 출처 있는 기억, 사용자 교정, 실행 경험, 검색과 워크플로우 개선이다. 필요시 PC에서 별도 학습한 모델의 평가/배포는 장기 과제로 분리한다.

## 3. 먼저 해결할 통합 결함·검증 공백

1. 의도 계획의 추천 읽기와 기존 완료 목표가 서로 달라, 짧은 후속 요청이 실제 조회 없이 끝나거나 완료 기준이 비는 경우가 있다.
2. 앱 이름을 언급한 평범한 대화와 실제 분석 지시를 구분해야 한다. 신뢰도 점수만으로 개인 자료 조회를 시작하면 안 된다.
3. 자료 대상 변경, 예를 들어 앞선 SMS 요청을 특정 메신저로 바꾸는 교정을 통합 회귀로 검증해야 한다.
4. 프로젝트 폴더 표시 이름을 파일 경로로 넘기는 연결을 고쳐야 한다.
5. 네이티브 JSON 출력은 문법 검증을 돕지만 올바른 대상·본문·날짜 선택을 보장하지 않는다. 실제 모델→도구→재조회 검사가 먼저다.
6. 구조화 전문 모델 선택은 성공한 검사 표시와 동일 모델 CPU 보고서를 요구한다. 표시를 실제 통과 후에만 저장하고 자동 선택을 검증해야 한다.
7. 직접 UI 도구/이미지/음성/일정 실행과 예외 일부가 공통 피드백 집계를 우회한다. 자연어 교정에서 개선 제안을 만드는 실사용 연결도 없다.
8. LiteRT 첨부의 8K 문맥, 역할별 모델과 음성 서비스의 준비 상태, 전체 문맥 토큰 예산을 실제 런타임과 맞춰야 한다.
9. DB는 schema2인데 릴리스 manifest와 검증기가 schema1 기준이다. 구버전→신버전 호환 배포를 조정해야 하며 무조건 APK만 되돌려서는 안 된다.
10. 기존 설명서·기능 목록·프로젝트 상태 문서가 최신 소스와 충돌한다. 한 검증 목록을 기준으로 함께 갱신해야 한다.

## 4. 재정렬한 실행 단계

각 단계는 소스·검사 결과·서명 APK·실기기 보고서·설명서 변경을 한 묶음으로 남긴다. 통과하지 않은 단계의 기능은 검증 완료로 표시하지 않는다.

### P0 — 현재 개발본 안정화와 기준 릴리스

- 기존 변경의 파일별 기준을 보존하고, 새 기능/사용자 소유 변경/검증 결과를 구분한다.
- 최신 전체 core/app 검사, lint, release APK 및 테스트 APK 빌드를 같은 소스 상태에서 실행한다.
- 요청 대상 교정, 앱 단순 언급, 프로젝트 경로, 누락 도구/잘못된 JSON, 읽기 복구/불확실한 쓰기 중복을 수정·검증한다.
- DB schema/업데이트 manifest/구버전 verifier를 맞추는 호환 배포를 설계한다. 실제 구버전 데이터와 승인을 보존해 1→2 전환과 이후 OTA를 검사한다.
- 현재 모델 파일 해시·런타임·문맥과 검증 보고서를 정합화한다. 모델 교체 자체를 이 작업에 포함하지 않는다.
- 최신 서명 APK 설치, 시작, 오프라인 기본 대화, 기존 기억·예약·모델 파일 보존을 확인한다.

**완료 조건:** 전체 검사 통과, 실제 설치 해시/소스 상태 확인, 데이터 보존, 호환 OTA 통과. 오래된 단위 검사 파일만으로 완료하지 않는다.

### P1 — 요청을 실제 행동으로 끝내는 핵심 에이전트

- 현재 요청·최근 대화·관련 기억을 이용해 목표, 필수 정보, 사용 가능한 자료, 다음 도구와 완료 증거를 정한다.
- 합리적인 기본값을 적용한다. 외부 행동에 꼭 필요한 정보만 최대 한 가지 질문으로 확인한다.
- 명시적 지시와 단순 언급을 구분하고, 최신 교정이 과거 계획을 대체하도록 한다.
- 읽기→추론→승인 필요한 변경→재조회 순서를 공통 실행기에 연결한다. 한 요청 6회 예산·취소·중복 방지를 유지한다.
- 실제 모델의 구조화 출력과 도구 선택을 검사하고, 모델 준비 상태를 실기기 성공 후 등록한다.
- 모든 실행 경로의 검증 결과를 집계한다. 구체적 오류 분류와 사용자 교정을 개선 제안에 연결한다.
- 일부 자료만 확인한 경우 부분 결과와 남은 연결을 제시하고 전체 완료를 주장하지 않는다.

**대표 검수:** 아래 인수 항목 중 로컬 핵심 20개(1–13,16,18,19,22,27–29)를 먼저 실행한다. 초기 개선 목표는 18개 이상 성공이며 잘못된 외부 변경·취소 후 실행·허위 완료는 0건이다. 안전/권한/삭제 관련 필수 검사는 전부 통과해야 한다. 초기 성공률은 진행 지표이고, 남은 실패를 완료로 간주하지 않는다. 계정·미디어·최종 배포를 포함한 30개 전체 인수는 후속 단계에서 수행한다.

### P2 — 기억과 실제 개인 자료의 수집·검색

- 직접 알려준 사실, 타인의 발언, 관찰, 추정, 승인 전 제안을 분리한다.
- SMS/가져온 대화/선택 녹음/일정의 분할 처리·출처·시점·중복·재시작 체크포인트를 연결한다.
- 한국어 의미 검색 후보를 실측하고 어휘/임베딩/관계 검색을 결합한다. 전체 기록 대신 핵심 프로필·요약·관련 항목만 전달한다.
- 교정 충돌 해결, 오래된 사실의 확인, 민감 정보 제외/보관 설정, 원본 삭제 후 검색·요약·재수집 전파를 완성한다.
- MD 조회/내보내기, 암호화 백업·복원, 처리 현황과 데이터 출처 화면을 정리한다.

**완료 조건:** 합성 기억 검색 평가에서 관련 사실 재현, 재시작 유지, 삭제한 정보의 재노출/재생성 0건. 단순 모델 응답이 아닌 DB·검색 결과로 확인한다.

### P3 — 매일 쓰는 연결: Gmail, 일정, 업무 메신저

1. **Gmail 우선:** 폰의 안전한 계정 인증, 메일함/검색/읽기/첨부/로컬 요약/답장 초안. 비밀번호·인증코드는 채팅으로 받지 않는다.
2. **네이버·회사 메일:** 실제 제공 프로토콜과 TLS, 계정 설정 확인. 회사 Outlook 설정을 구체적인 서버 정보로 완성한다.
3. **일정·알림:** 문자/메일의 일정 후보→중복/시간 확인→승인→등록→재조회. 수정·삭제·타이머·실제 알림/재부팅/절전 복원을 검증한다.
4. **메디통:** 앱 버전별 수신 자료, 첨부 저장·열기, 답장 초안/허용 규칙, 발송 결과 확인. 실제 업무 상대에게 개발 테스트 메시지를 보내지 않는다.
5. **카카오·텔레그램:** 수신 세션과 과거 내보내기/가능한 공식 연결을 구분해 제공하고 실제 분석 범위를 표시한다.
6. **Chrome·지도·연락처·전화·메시지:** 공식 Intent/API별 동작 확인과 준비/완료 구분. 기존 허가를 반복 요청하지 않는다.

**완료 조건:** 각각 실제 계정/허용 자료로 읽기→요약→후속 작업의 결과가 확인되고, 연결이 없는 경우 정확한 다음 한 단계를 안내한다.

### P4 — 한 채팅 화면과 스마트폰 프로젝트

- 기본은 채팅, 별도 전문 화면은 이미지 작업실, 나머지는 설정/기록/참고로 정리한다.
- 키보드가 열린 상태에서 입력·첨부·보내기·중단·모델 선택이 동작하게 한다.
- Markdown·표·코드·출처·파일 카드, 실패 재시도와 첨부 복원, 여러 턴의 파일 참조를 연결한다.
- 선택한 프로젝트별 대화·기억·파일을 구분하고, 파일 읽기→수정안/diff→확인→저장→재조회→복원을 제공한다.
- 공유 파일 접근과 프로젝트 폴더 범위를 표시한다. 코드 저장, 코드 실행, Android 앱 빌드는 별도 기능으로 검증한다.
- 아이콘·타이포·대비·모션·큰 글씨·긴 응답·접근성의 실기기 시각 검사를 한다.

**완료 조건:** 채팅에서 문서 작성·쇼핑·파일 분석·프로젝트 수정을 수행하고, 화면 이동 없이 결과/중단/파일을 확인한다. 원본 보존·경로 이탈·오래된 해시 쓰기 검사를 통과한다.

### P5 — 문서·미디어 품질

- Office: 표/수식/서식 보존 편집과 내보내기. 지원하지 않는 기능을 명확히 구분한다.
- PDF: 스캔 OCR, 표·페이지 출처, 장문 전체 처리, 양식/편집을 단계적으로 추가한다.
- 쇼핑: 상품/옵션/배송/최신성 일치, 직접 상품 링크, 확인된 비교 근거로 가성비 설명. 사이트 차단·미확인 가격을 최저가로 제시하지 않는다.
- 이미지: 채팅과 작업실의 참조 사진 전달, 같은 시드·다른 참조의 실제 영향, 원본 보존·취소·모델 해제를 검증한다.
- 의료 교육: 거절문을 그림 설명으로 렌더링하지 않고, 용어·스타일·제외 조건을 보존한다. 생성 도해의 정확성을 자동 보증하지 않으며 참조 출처/주석/검토를 지원한다.
- 영상/음성: 실제 파일의 전사·자막·시간축 분석, 샘플 프레임과 전체 영상 분석 구분, 기본 편집, 로컬 생성형 영상 가능성 실측.

**완료 조건:** 형식별 대표 파일의 내용·범위·출처·파일 저장 결과 검증과 선택한 실제 녹음 평가를 통과한다. 시각 품질/내용 정확도는 생성 파일 존재 여부와 별도로 평가한다.

### P6 — 능동형 비서와 안전한 확장

- 일일 브리핑, 회의 전 준비/이동 확인, 반복 루틴과 승인 대기 알림을 구현한다.
- 백그라운드는 이벤트·예약을 중심으로 운영하고 LLM은 필요한 순간만 로드한다. 배터리/절전/재부팅/권한 회수/중단을 검사한다.
- 익명화된 로컬 작업 통계로 공개 확장 카탈로그를 기기에서 평가한다. 개인 이력·메일·기억을 GitHub 검색 질의로 보내지 않는다.
- 스킬/플러그인/MCP의 실제 설치·실행 환경과 버전/권한/네트워크/의존성/격리/삭제 체계를 만든다.
- 서명·해시·출처·라이선스·호환성 검사를 실제 설치 경로에 연결한다. 검사기만 존재하는 상태를 설치 지원으로 표시하지 않는다.

**완료 조건:** 실제 확장 하나를 점검→연결→사용→해제/삭제하고, 악성/손상/과권한 후보는 실행되지 않는다. 추천 근거와 필요한 새 권한을 사용자가 확인할 수 있다.

### P7 — 자동 개선·PC 의존 축소·최종 인수

- 실패 유형/성공률→개선안→프로젝트 패치→회귀 검사→서명 빌드→배포→설치 후 검사 흐름을 연결한다.
- 폰의 코드/프로젝트 작업과 GitHub CI를 연결하되 개인 DB·업무 자료·키가 저장소에 들어가지 않게 한다.
- 검증된 동일 권한 업데이트의 자동 적용, 새 권한/출처 검토, DB 호환 복구를 완성한다.
- 실제 요청별 성공률, 지연, 메모리·발열·배터리 보고서를 기록한다. 모델/파일 해시가 바뀌면 이전 수치를 그대로 적용하지 않는다.
- 최신 APK·소스·해시·변경점·간단 설치/사용/복구 안내서를 같은 버전으로 전달한다.
- 선택적 SmartThings와 별도 스토리 앱은 핵심 비서 인수 이후 독립 작업으로 분리한다.

**완료 조건:** PC가 꺼진 상태의 일상 대화/도구/기억/예약이 동작하고, 패치 배포와 데이터 보존을 실기기에서 확인한다. 필수 인수 30개가 같은 릴리스에서 모두 통과해야 최종 인수를 완료한다. 폰 자체 소스 빌드 능력은 별도 증거가 있어야 완료로 표시한다. 사용자 요청의 미해결 항목이 남으면 전체 목표는 미완료로 유지한다.

## 5. 대표 인수 시나리오 30개

1. 맥락 없는 분석 요청에는 필요한 자료 한 가지만 확인한다.
2. 분석 요청→메신저 지정→전체 대화의 짧은 후속 요청에서 같은 질문을 반복하지 않는다.
3. SMS를 요청했다가 특정 메신저로 바꾸면 이전 자료 대상이 남지 않는다.
4. 앱을 단순 언급한 대화만으로 개인 메시지를 조회하지 않는다.
5. 현재 시각과 일정 날짜를 Asia/Seoul로 일관되게 계산한다.
6. SMS의 실제 범위·건수·일정 후보와 불확실한 날짜를 표시한다.
7. 일정 등록은 승인 후 저장하고 실제 ID/시각을 재조회한다.
8. 같은 일정 재등록·취소·모호한 날짜에서 중복/잘못된 변경이 없다.
9. 실제 로컬 리마인더가 도착하고 앱 재시작 후 남는다.
10. 승인 전/취소 후 알람·외부 작업을 완료로 표시하지 않는다.
11. 알려진 가족/선호를 사용하고 관계·나이·지역을 새로 지어내지 않는다.
12. 사용자의 교정이 더 오래된 기록보다 우선한다.
13. 잊은 정보가 검색/요약/백그라운드 수집으로 재생성되지 않는다.
14. Gmail 실제 검색→메일 요약→초안 작성이 동작한다.
15. 회사 메일 설정과 연결 실패 원인이 실제 서버/TLS 근거로 설명된다.
16. DOCX/XLSX/PDF 요청이 실제 파일과 읽기 결과로 확인된다.
17. 긴 문서·스캔 PDF는 처리/누락 범위를 정확히 표시한다.
18. 프로젝트 파일은 먼저 읽고 해당 버전 해시가 일치할 때 수정한다.
19. 프로젝트 밖 경로·잘못된 파일·오래된 해시 변경을 거부한다.
20. 여러 턴의 첨부 참조·실패 재시도에서 사용자가 자료를 불필요하게 다시 선택하지 않는다.
21. 키보드/큰 글씨에서도 보내기·첨부·중단·모델 선택이 보인다.
22. 쇼핑 결과는 실제 출처·상품/옵션·조회 시각·확인된 가격을 가진다.
23. 참조 이미지 변환은 원본을 보존하고 입력 사진에 따라 실제 결과가 달라진다.
24. 정상 의료 도식 요청의 용어·제외 조건이 바뀌지 않는다.
25. 실제 한국어 녹음 전사·중단·이어하기가 동작한다.
26. 영상 샘플 분석을 전체 영상/음성 분석으로 표시하지 않는다.
27. 문서/메시지/확장 속 명령으로 도구 권한이나 외부 전송이 생기지 않는다.
28. 모든 실행 경로의 완료·준비·실패가 올바르게 집계되고 초기화 후 과거 실행이 다시 기록되지 않는다.
29. 손상 모델/업데이트·과권한 확장을 실행하지 않고 모델 전환 때 이전 메모리를 해제한다.
30. 최신 모델 조합으로 오프라인·10분 사용·재시작·서명 OTA·DB 보존을 통과한다.

## 6. 앞으로의 완료 보고 방식

매 작업 보고에는 변경한 실제 사용자 동작, 같은 소스의 검사 결과, 설치 APK/서명/해시, 실기기 시나리오, 남은 실패와 처리하지 않은 범위를 포함한다. 미확인 기능은 성공 개수에 넣지 않는다. 초기 단계가 통과한 뒤 다음 단계로 넘어가되 사용자 인증처럼 외부 입력이 필요한 항목과 독립 개발은 병행한다.
