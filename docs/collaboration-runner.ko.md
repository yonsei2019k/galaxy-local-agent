# 협업방에서 개발 이어가기

PC의 기존 협업방을 메시지 전달에 사용합니다. Windows 작업 `ZipHap Event Collaboration Runner`가 사용자 로그인 상태에서 실행되며 협업방의 순번을 읽습니다. Codex 채팅에 주기적으로 프롬프트를 넣던 자동 작업은 일시중지합니다. 기존 감시기는 계속 수신합니다.

- 실행기는 로컬 승인 목록에 있는 구체적인 작업만 처리합니다. 시작 시 등록한 목록과 로컬 `queue.json`에 추가된 항목을 순번대로 처리합니다. 등록된 기존 항목의 정의를 덮어쓰지 않습니다. 남은 항목이 없으면 모델을 부르거나 협업방에 게시하지 않습니다.
- Codex가 등록한 검토 요청이 실제 협업방에 들어오면 Claude가 선택 가능한 회귀 검토를 수행합니다. Claude 답변이 협업방에서 확인된 뒤 해당 Codex 작업이 실행됩니다. 이미 실제 검토를 받은 작업은 그 검토를 재사용할 수 있습니다. Claude와 Codex는 각 한 건씩 병행합니다.
- 메시지 자체는 실행 권한이 아닙니다. 협업방 순번·송수신자·메시지 ID·본문 다이제스트가 로컬 작업의 현재 단계와 맞을 때만 진행합니다. 새 실행은 로컬에 등록된 소스와 시험 범위에 한정합니다. Claude에는 도구 접근을 부여하지 않습니다. Codex에 필요한 추적 소스만 전달합니다. 모델이 내놓은 수정은 지정 파일·기준 소스에 대조한 후 로컬 실행기가 적용하고 승인된 집중 시험을 실행합니다.
- SQLite에는 작업·단계·게시 순번·검증된 후보 커밋을 보존합니다. 작업 결과를 게시하기 전에 기록하고 같은 게시 ID는 다시 작성하지 않습니다. 실행 중 PC가 꺼졌다면 해당 단계의 후보 파일과 시험 결과를 확인할 때까지 재실행하지 않습니다. 로그인 전용 상태는 Claude 로그인 여부만 확인합니다. 로그인 성공 뒤 대기 작업을 실행합니다.
- 결과 커밋은 후보 작업 트리에 남습니다. 휴대폰 설치, PC 워커 교체, 푸시와 외부 시스템 작업은 기존 별도 절차에서 다룹니다. 백그라운드 실행기를 잠시 멈출 때는 상태 파일에서 활성 단계가 없는지 확인하고 로컬 런타임의 `STOP` 파일을 사용합니다.

로컬 런타임은 등록 시 설정한 경로의 `config.json`, `queue.json`, `dispatch.sqlite3`, `status.json`을 사용합니다. 구독 계정은 양쪽 CLI의 기존 로그인을 사용합니다. 머신 경로·기기 정보·메시지 원문은 커밋하지 않습니다.
