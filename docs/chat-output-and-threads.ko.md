# 긴 답변·다중 채팅 구현 계약

2026-10-31. 이 문서는 구현 계약이며, 테스트 실행·설치 증거와 구분한다.

## 소유 범위와 협업

- 채팅 기반 담당: `ChatRunCoordinator`, `LongAnswerWriter`, Room v3, 추론 종료 이벤트, 채팅 탐색·첨부 격리.
- 별도 진단 작업: 요청 의도 분류와 native/web 선택, 공통 변경 기록. 해당 작업은 장문·방 격리 코드를 보존한다.
- 같은 폴더에서 작업하므로 빌드·서명·실기기 실행은 직렬로 수행한다. 진행 중 소스 변경이 있으면 최종 APK를 다시 빌드한다.
- 기존 사용자의 미커밋 소스를 보존한다. 다른 작업의 수정까지 임의로 묶어 커밋하거나 공개하지 않는다.

## 사용자 동작

- 긴 답변은 같은 답변의 1부·2부·3부로 나누어 작성한다. 전체 복사·내보내기는 모든 저장 구간을 포함한다.
- 구간별 토큰 한도는 답변 전체의 글자수 제한이 아니다. 기본 출력 예산은 일반 768, 상세 1536, 긴 글 2048토큰이며 실제 문맥 여유 안에서 조정한다.
- 자동 생성은 한 번에 최대 4구간 또는 10분이다. 이후 미완성 상태와 계속 버튼을 보존한다. 전원·자원 부족에도 무한 생성을 보장한다는 뜻은 아니다.
- 사용자 중단은 자동 재개하지 않는다. 저장된 텍스트 이어쓰기는 명시적인 계속 버튼으로 재개하며 이전 도구를 재실행하지 않는다.
- 새 채팅은 DB에 저장한다. 방별 초안·모델 설정·첨부를 복원한다. 이름 변경·고정·보관·복원·복제·이동·분기·삭제를 구분한다.
- 본문·제목 검색은 모든 저장된 대화 버전을 조회하고 내보내기는 모든 분기의 순서와 공유 메시지 ID를 보존한다. 화면은 최근 60개부터 필요한 기록을 추가로 조회하며, 화면 밖의 청크를 매 갱신마다 모두 불러오지 않는다.
- 방·분기·메시지·블록·픽셀 위치를 저장한다. 스크롤 저장은 작성 중인 초안과 모델 설정을 덮어쓰지 않는다. 폴더 선택은 선택한 프로젝트 ID에 고정하고 미저장 설정을 유지한다.
- 보관은 되돌릴 수 있다. 영구 삭제와 내용 비우기는 별도 확인하며, 파생 기억을 지울지 선택한다. 실제 외부 파일·일정은 대화 삭제만으로 지우지 않는다.

## 실행·저장 불변 조건

- 화면에 표시하는 스트림은 먼저 암호화 DB에 기록한다. `MessageChunk`의 구간 ID·순번은 중복 전달을 검증한다.
- 출력은 `Delta`와 `Finished(GenerationSummary)`로 전달한다. GGUF의 EOG/상한은 네이티브 근거, LiteRT의 미제공 종료 이유는 UNKNOWN/추정으로 기록한다.
- 완료된 Flow를 곧바로 사용자 목표 완료라고 간주하지 않는다. 출력 상한, 취소, 문맥 초과, 오류를 별도로 보존한다.
- 종료 근거가 UNKNOWN이면 자동 반복 없이 일시정지와 수동 이어쓰기를 제공한다. 1MiB 구간 보호 한도는 이미 받은 Delta를 버리지 않고 저장한 뒤 다음 구간을 기다린다.
- 부분 JSON은 이어 붙여 실행하지 않는다. JSON 검증·도구 허용 범위·실제 실행 결과 검증을 통과해야 한다.
- 한 번에 하나의 대형 모델만 실행한다. 다른 방의 요청은 대기하며 결과·승인·첨부·프로젝트 폴더는 원래 실행에 고정한다.
- 제출 DB 커밋 이후 첨부 저장이 실패하면 실제 대기열 취소 상태를 다시 읽는다. 취소가 확인되지 않은 요청을 새 ID로 재전송하지 않는다. 삭제·비우기 이후 오래된 첨부나 결과로 방을 되살리지 않는다.
- 대화 분기는 그 시점까지의 실제 메시지와 첨부 참조를 유지한다. 원본 방을 지워도 다른 방의 공유 첨부를 함께 지우지 않는다. 근거가 남지 않은 이전 첨부 관계는 임의로 복원했다고 표시하지 않는다.
- Room v3는 기존 DB 이름·Keystore 키·메시지 ID를 유지한다. 1→2→3 및 2→3 이관을 검증한다. 파괴적 재생성을 사용하지 않는다.
- 승인된 사용자 기본정보와 프로젝트 자료를 구분한다. 도구와 문맥은 `repository.forThread`로 연결한다.
- 긴 파일의 발췌문을 읽은 상태에서는 원본 전체를 덮어쓰지 않는다. 기존 파일 해시와 전체 읽기 근거를 확인하고 저장 후 다시 검증한다.

## 검증 게이트

- JVM: 종료 원인, 실제 토큰 계수, 출력 예산, 청크 처리, 긴 화면 문자열 보존.
- `chatDataValidationApproved=true`: 합성 DB의 v2→v3, 긴 본문·초안·분기·격리·삭제·재시작.
- `generationEventsApproved=true`: 캐시된 실제 모델의 cap/EOG/취소 구별.
- `longAnswerValidationApproved=true`: 실제 모델의 여러 부 저장, 같은 실행에서 계속, 취소 체크포인트.
- `attachmentScopeApproved=true`: 합성 첨부의 방 전환·사용권·복원·삭제와 초안 암호화 격리.
- `longAnswerFinishValidationApproved=true`: 합성 엔진 이벤트와 실제 암호화 DB로 UNKNOWN·저장 경계·JSON·중복 이어쓰기 검사. 실제 모델 속도 검사는 별도다.
- 실제 휴대전화 모델 검사는 `deviceOnly=true`를 고정해 PC 추론을 휴대전화 성능으로 기록하지 않는다. 수동 이어쓰기 스냅샷도 이 설정을 보존한다.
- 빌드 성공, 기기 테스트 통과, 사용자 실제 작업 성공은 서로 다른 증거다. 최종 기록에는 설치 APK 해시와 실제 실행한 테스트만 적는다.
