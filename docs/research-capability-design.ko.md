# 문맥 기반 작업 계획과 조사 능력

## 목적과 구현

사용자 요청의 특정 단어나 문장 형태에 행동을 고정하지 않는다. 현재 요청과 최근 대화를 읽은 로컬 LLM이 목표·대상 종류·자료 출처·필수 도구·제약을 계획한다. 호스트는 이 계획을 실행 권한으로 간주하지 않고 형식·도구 범위·기존 승인·실행 결과를 검사한다. 미완성 계획을 예전 안내 문구로 대체하지 않는다.

조사에는 서명된 앱에 포함한 `skills/research/SKILL.md`를 실제로 적용한다. 문제와 확인 기준을 정하고, 공개 검색 → 모델의 다음 행동 판단 → 관찰 URL 원문 읽기·추가 검색 → 근거와 한계를 포함한 답변으로 이어진다. 새 스킬은 모델 가중치의 재학습이나 외부 플러그인 설치를 의미하지 않는다.

`search_shopping`은 실물 상품 카탈로그다. 의미 계획에서 상품으로 분류한 경우에만 실행한다. 서비스 견적·항공 운임·예약 가능성은 해당 자료를 실제로 조회할 수 있는 별도 기능이 필요하며, 현재 그 기능은 없다. 공개 웹은 관련 방법과 공개 정보를 조사할 수 있으나 실시간 요금·가능 여부·전체 최저가를 보장하지 않는다.

업무 일정과 항공편을 결합하는 요청은 필요한 공항·날짜·가능 시간과 운임 조건을 구분해야 한다. 개인 일정의 원문을 외부 검색으로 보내지 않는다. 현재 지원 기능으로 끝낼 수 없는 부분을 명시하고, 관련 없는 상품 검색으로 진행하지 않는다.

## 외부 스킬·플러그인 도입 기준

확장 프로그램은 실제 Android 런타임에서 실행되는 도구 연결이 있어야 한다. 데스크톱 Codex에 설치한 스킬은 휴대폰의 Gemma가 자동으로 실행하는 도구가 아니다. 현재 앱의 실행형 MCP 호스트가 완성되어 있다고 주장하지 않는다. 공식 검색·문서·항공 정보 등의 연결을 추가할 때는 제공 자료, 인증, 비용, 실제 시점·출처, 기기 내 개인 자료 경계를 검증한 뒤 연결한다.

현재 내장 공개 검색과 원문 읽기를 먼저 실제 조사 루프에 연결했다. 외부 제공자나 유료 API 계정을 생성·구매하거나, Android에서 실행할 수 없는 서버를 설치했다고 표현하지 않는다.

## 근거와 검증

Gemma 공식 문서는 모델의 도구 호출 제안, 애플리케이션의 실행, 도구 결과를 이용한 최종 답변을 구분하며, 실행 전 검증을 요구한다. [Gemma 4 function calling](https://ai.google.dev/gemma/docs/capabilities/text/function-calling-gemma4)

조사는 관찰한 결과에 따라 다음 방향을 바꾸는 작업이므로 고정된 단발 검색 경로만으로 충분하다고 보지 않는다. 이 구현은 휴대폰에서 한 모델씩 사용하며 다음 행동 판단과 결과 검토를 순차 처리한다. [Anthropic 연구 시스템 설계](https://www.anthropic.com/research/multi-agent-research-system)

MCP는 도구와 문맥을 연결하는 프로토콜이며, 애플리케이션의 추론과 문맥 운영 자체를 대신하지 않는다. [MCP architecture](https://modelcontextprotocol.io/docs/learn/architecture)

실제 검증·모델·빌드·설치 상태는 `agent-change-log.md`를 기준으로 한다. 단위 검사는 JSON·도구·자료 범위·조사 예산 계약을, 실기기 검사는 실제 모델의 변형 문장·다중 턴 해석과 조사 결과를 확인한다. 어느 검사도 모든 미지의 문장에 대한 성공 보장은 아니다.
