# GitHub 서명 자동 업데이트

배포 브랜치는 `codex/internal-release`다. 이 작업 폴더도 같은 원격 브랜치를 추적한다. 검토한 소스 변경을 커밋하고 `git push`하면 `.github/workflows/android.yml`이 전체 core/app JVM 테스트, 릴리스 lint, APK 빌드를 실행한다. 성공한 빌드만 기존 GitHub Secrets로 APK와 `update.json`을 서명하고 최신 릴리스로 게시한다. 별도 개발 브랜치와 PR은 자동 설치용 릴리스를 만들지 않는다.

CI 버전 코드는 `2000 + workflow run number`이며 두 작업이 같은 값을 사용한다. 과거 수동 설치1090보다 크고 다음 실행마다 증가한다. 버전 이름은 `0.1.<run number>`다. 이전 버전 APK를 새 버전인 것처럼 배포하거나 설치된 버전 이하의 APK로 다운그레이드하지 않는다.

폰의 기존 업데이트 관리자가 GitHub 최신 릴리스의 서명된 `update.json`을 읽고 발행 키, 패키지, 버전, APK SHA256, 설치 서명과 권한·기능 변경을 검사한다. 기존에 승인된 범위의 업데이트만 자동 설치를 요청한다. 새 권한·기능은 기존 검토 절차를 따른다. 기존 메모·리마인더 권한의 실제 승인 범위만 검증한 다음 APK 해시로 이관한다.

앱을 열어 둔 동안에는 다른 작업이 없을 때 약60초마다 확인한다. 백그라운드는 Wi-Fi 등 종량제 아닌 네트워크 조건으로15분 주기의 WorkManager 예약을 사용하며, 실제 실행 시점은 Android가 지연할 수 있다. 계산·이미지 작업 중에는 설치를 미룬다. 앱을 강제 중지했거나 네트워크가 없으면 즉시 업데이트되지 않는다.

설치 출처 허용은 Android 시스템 화면을 통해 받는다. 이미 허용된 기기는 다시 설정할 필요가 없다. 설치 시 시스템이 추가 확인을 요구하면 앱 알림의 설치 확인을 연다. 모든 기기에서 즉시·무확인 설치된다고 보장하지 않는다. ADB와 Tailscale은 이 배포 경로의 필수 조건이 아니다.

GitHub 빌드 성공, 릴리스 게시, APK 다운로드, 설치 요청, 실제 설치 버전·바이트 확인은 각각 별도 증거다. 실제 결과와 이미지 복구 보존은 PROJECT_STATE 및 docs/agent-change-log.md에 기록한다. 응답 스트리밍, PC Codex 채팅방 동기화, GPT/Claude 개별 모델·추론 수준 선택은 이 업데이트 연결과 별개의 미완료 기능이다.
