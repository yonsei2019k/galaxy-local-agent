# 기존 계획과 실제 진행 대조

## 후속 진행: PC·클라우드 도구 연결과 통합 대화방은 구분

아래 최초 감사 뒤 실제 MCP→PC broker→폰 실행기가 추가됐다.1086 별도 읽기 시험에서 실제 클라우드 PC2/폰2 호출을 확인했고,1088 일반 폰 대화에서는 Codex→승인1→메모 저장/검색/같은 메모 전체 읽기1회가 통과했다. 앞선 실패와 수정/설치/기기 근거는 PROJECT_STATE/agent-change-log를 따른다. 현재 일반 클라우드 대화의 지원 범위는 phone-only 첫5도구이며 PC 파일 작업용 사용자 UI가 추가된 것은 아니다.

사용자가 다시 확인한 다음 항목은 계속 필수 실행 차이로 남긴다.

| 항목 | 현재 확인한 상태 | 필요한 연결 |
|---|---|---|
| 집합스튜디오 채팅에서 PC 에이전트에 지시 | 이번 Android 변경에서 Studio 요청 수신/응답 UI를 연결하지 않음 | 원래 conversationId/runId·발신 앱·scope·캡처 권한을 고정해 전달하고 같은 대화로 실제 결과/질문/승인/중지 상태 반환 |
| 폰·Studio·PC의 통합 에이전트 대화방 운영 | 폰 부모 대화의 실행과 PC headless broker는 연결. 공유 대화 저장소/PC companion 화면은 미완 | 한 사용자 대화를 기준으로 하위 에이전트 작업을 연결하고 방별 문맥·결과·권한이 섞이지 않게 관리. 개발 채팅방3개를 제품 통합의 증거로 사용하지 않음 |
| Claude/ChatGPT 작업 처리 | 새 직접 도구 경로는 기존 ChatGPT 로그인으로 실행한 Codex CLI가 실기 근거. 별도 기존 Claude 선택형 응답 엔진 코드가 있음 | Claude의 동일 도구/승인/취소/검증 경로 실제 연동은 추가 필요. 두 서비스의 웹·데스크톱 채팅방 자동 운영·동기화를 구현했다고 하지 않음 |
| 쿠팡·티맵·카톡 화면 작업 | 기존 등록 도구와 새 클라우드 첫5도구의 범위가 다름 | 사용자 추가 시나리오는 smartphone-scenario-evaluation 문서에 기록. 기존 화면 조작 엔진 재사용도 실제 국내 앱/버전/언어/대상/취소/증거 조건으로 비교 |

Studio 연동은 자연어 단어를 분류하는 새 고정 라우터로 대체하지 않는다. 작업 결과는 발신 대화에 묶고, 모델·다른 방·외부 문서의 메시지가 새 실행 권한이 되지 않도록 한다. 모델의 완료 문장, 하위 작업의 종료, PC에 요청을 보낸 상태와 실제 폰·PC 효과 완료는 각각 구분한다.

2026-11-15. 사용자 요청에 따라 통합 설계, 현재 Android 실행 경로, 배포 PC worker, 오프라인 시제품, 설치·시험 영수증을 대조했다. 새 PC 제어 서비스나 실행기를 설치한 보고가 아니다.

## 원래 계획

[통합 기준](README.ko.md)의 제품 목표에는 한 대화에서 PC·폰 작업과 허용된 외부 에이전트를 함께 제어하는 내부 배포가 명시돼 있다. [상세 구조](dual-device-orchestration.ko.md)는 PC broker, 실행기/provider, Android client, 같은 작업의 양쪽 화면 제어를 설계한다.

첫 연동에서는 폰의 기존 요청·자료·승인 권한을 부모로 보존하고 PC가 하위 작업을 조율한다. PC 에이전트가 두 기기의 허용된 실행기를 호출하는 기능도 필요한 범위다. 폰과 무관한 PC 독립 부모 작업은 후속이다. 이 권한 원장 배치와 PC의 실제 작업 조율 여부는 구분한다.

## 현재 판정

| 계획 항목 | 확인된 상태 | 판정 |
|---|---|---|
| 스마트폰 비서·한 대화·기존 자료 보존 | 기존 앱ID/서명/데이터를 유지한1085 설치,104개 도구 등록 | 기반 구현, 모든 업무 성공을 뜻하지 않음 |
| PC 로컬 추론·연결 | 실제9B/선택형4B 호출, 설치1085의 원래 인증서 pin을 사용하는 직접 Tailscale 검사88ms PASS | 실제 사용 확인. 외부망 전환 미검증 |
| PC·폰 오케스트레이션 계약 | 공개 wire와 `pc-worker/orchestration/` 메모리 상태기계. 이번 감사에서도 순수38검사 PASS | 설계·오프라인 시제품만 있음 |
| PC 에이전트의 양 기기 작업 실행 | 실제 broker 서비스/인증·영속 원장/provider adapter/PC executor/Android command client 연결 없음 | 핵심 미구현 |
| PC·폰 동일 작업의 승인·중지·재개 | Android 자체 요청·승인·취소는 있음. PC child와 이벤트/revision 동기화 없음 | 통합 기능 미구현 |
| 외부 PC 에이전트·MCP | 로컬 LLM 위임용 코드와 개발 도구는 있음. 제품의 범용 agent/session dispatch는 없음 | 제품 연동 미구현 |
| 개발 채팅3개 | 모델·추론, 도구·문제해결, 검증·내부배포 채팅 생성·고정 확인 | 개발 협업 구현. 제품 실행기와 별개 |
| 개인 PC·폰을 쓰는 팀 배포 | Android 빌드·서명·폰 업데이트 검증. 통합 PC companion 설치·온보딩·지원 기기 행렬은 미완료 | 내부 시범 배포 준비 미완료 |

`ChatRunCoordinator`가 Android에서 계획·다음 행동·도구 실행을 관리하고 PC worker는 추론·이미지·미디어 요청을 처리한다. 배포 `server.py`와 앱에는 Python 시제품의 submit/control/observe 연결이 없다. 앱의 `LocalOrchestration` 이름은 모델 선택 기능이며 두 기기 작업 broker가 아니다. 기존 제한된 브리핑 companion과 개발용 ADB 설치·검사도 범용 제품 제어의 증거가 아니다.

## 최근 개선의 실제 범위

- 설치1085: 전체 빌드7분3초, core945+app877=1822 JVM 검사, lint 오류0, 동일 설치본의 통제 기기73검사 PASS. 새 partial-AFTER 질문 피드백은 scripted semantic/direct의1회 재판단 및 재질문 중단까지 확인했다.
- 실제1085 메모3시도는1성공/2중단이다. 성공87303ms는 정확 대상·승인1·수정1·전체 AFTER 전달 ACK·최종 답변·정리를 검증했다. 실패는 검색 제목 복사 오류30705ms/수정 후 첫 재조회 전 재확인47398ms다. 실패도 영수증/원문 캡처/fixture·설정 정리가 확인됐으며 완료로 재분류하지 않았다. 실패 보고서의 idle=false와 후속 독립 empty/idle 확인도 분리한다. QA용 메모·제한된3도구 조건이며 일반 사용자 업무 완료율이 아니다.
- 이전1084의9B323731ms/4B direct80972ms/4B default 반복102301ms 성공과1실패는 해당 버전의 별도 근거다. 저장된 동일 보고서 앞의 버려지는 마지막 일반 생성이0회인 경로를 확인했다.
- 원20개 합성 요청의4B 단일 계획 비교는 compact schema9/20, 기존 action별 strict schema20/20 파서 수용이다. 각20건 기록/모델 load1회/실제 wire·준비 hash·컴파일 바인딩/자기 owner unload·idle 확인, 도구 효과0이다. strict 조건은 검증된1085 core를 재사용하고 별도 bridge를 컴파일했다. 의미 정확도·실제 실행·앱의2회 repair 절감은 아직 증명하지 않았고 앱에는 적용하지 않았다.
- queryQuoteId 및 첫 AFTER 조회 전 질문 피드백은 ignored 소스 후보로 동결했다. 미컴파일·미설치이며 현황 보고 전에 통합하지 않았다.

## 계획 대비 지연과 다음 우선순위

설계의 단계1 이후 실제 서비스·실행기 연결이 진행되지 않은 채 단계0의 메모·추론·읽기쓰기 최적화에 작업이 집중됐다. 이 개선을 PC·폰 제어 구조 완성으로 집계할 수 없다. 핵심 연동을 미룬 진행 관리의 문제다.

다음 중심 작업은 기존 계획의 실행 연결이다. 현재 권한/동의·취소 경계를 유지한 PC broker·provider 발견/세션 조회를 먼저 연결하고, 격리 QA workspace의 PC 작업과 기존 Android ToolExecutor를 동일 작업·revision에 묶는다. 이어 실제 PC 산출물과 폰 결과를 함께 재조회하는 하나의 전체 업무, 양쪽 중지·재개·재접속, PC companion/설치·팀 온보딩을 검증한다. 이 순서는 앞으로 할 작업이며 완료 판정이 아니다. 일반 터미널이나 개발용 ADB를 제품의 무제한 제어 API로 노출하지 않는다.
