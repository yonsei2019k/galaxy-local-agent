# PC·스마트폰 오케스트레이션 통합 기준

2026-11-15. 제품 목표는 **기본 스마트폰 비서를 보존하면서 같은 대화에서 PC·폰 작업과 허용된 외부 에이전트를 함께 제어하는 회사·팀 내부 배포**다. 아래 결정은 구현 순서를 정한다. 설계나 개발 채팅 연결을 제품의 실제 외부 에이전트 연결 완료로 표시하지 않는다.

## 확정한 경계

1. 첫 연동은 폰의 기존 대화/run이 부모 권한을 소유하고 PC가 하위 작업의 최소 상태 원장을 관리한다. PC 화면은 같은 작업을 제어한다. 폰과 무관한 PC 독립 부모 작업은 후속 계약이다.
2. 기본 추론은 paired-PC 로컬이다. 외부 provider·모델·MCP·자료 전송 허용은 별도 캡처하며, `allowCloudText`를 재사용하지 않는다. legacy 작업의 외부 실행 허용 기본값은 false다.
3. 모델은 요청과 다음 행동을 해석한다. 호스트가 실제 권한·범위·대상 버전·단회 승인·취소·예산·관찰 결과를 검사한다. 문서·메시지·MCP·agent 응답은 권한 발급자가 아니다.
4. 외부 agent의 도구 실행 전 검사와 지원 OS 격리를 실제 검증하지 못하면 관찰·제안만 제공한다. 일반 터미널·ADB·무제한 MCP를 제품 실행 우회로로 노출하지 않는다.
5. 제출 의도와 host가 발급하는 binding/grant/approval/receipt는 다른 타입이다. JSON 필드만 복사해 권한이나 VERIFIED 결과로 승격하지 않는다. 제품 endpoint는 인증·ledger 조회·취소/만료 검사가 구현된 뒤 연다.
6. 제어는 epoch/revision/CAS, 전송은 idempotency key와 payload digest, 이벤트는 sequence/cursor에 묶는다. 취소 요청과 실제 취소 ACK를 구분한다. 이미 시작한 효과가 불명확하면 자동 재실행하지 않는다.
7. PC 개인 원문·응답·trace는 기본 RAM-only다. 중복 방지·취소·재조회에 필요한 최소 metadata/digest/reference는 암호화·TTL을 갖춘 원장에 보관할 수 있다. 원문 영속 보관은 별도 허용이 필요하다. 외부 CLI 자체의 보관을 통제하지 못하면 그 제한을 표시하고 해당 자료 작업을 제공하지 않는다.
8. agent 성공 문장·프로세스 종료0·Intent 준비는 목표 완료가 아니다. 호스트 관찰·산출물 byte hash·실제 저장/예약/발송 readback을 결과 종류에 맞게 확인한다. 부분·실패·질문·PREPARED를 긍정 업무 완료로 집계하지 않는다.
9. 기존 모델 RAM lease·실행 중 업데이트 차단을 유지한다. 독립 읽기/설계는 병렬로 하되 같은 파일·동일 승인·로컬 모델·폰 설치는 한 소유자가 직렬화한다.

단계1은 실행 권한을 발급하는 제품 서비스가 아니다. 최종 wire와 Kotlin/Python의 동일 golden fixture 검사가 준비되기 전 Android 실행 경로에 연결하지 않는다. 별도 Gradle 모듈이나 전체 coordinator 교체를 먼저 요구하지 않는다.

세 개발 채팅은 모델·추론(xhigh), 도구·문제해결(high), 검증·내부배포(xhigh)로 역할을 나눈다. 각 작업은 파일·기준 hash·검사 범위를 인계한다. 통합 담당만 공유 계약 반영, Gradle·서명·설치·실제 모델 창·커밋을 소유한다. 채팅 간 보고는 같은 버전과 증거 종류로 연결하고 다른 작업의 결과를 합쳐 성공률을 만들지 않는다.
