## 플랫폼 확인

현재 앱은 target37이며 `ACCESS_LOCAL_NETWORK`를 선언하고 `PcLocalNetwork.allowed`를 검사한다. Android17/target37부터 LAN 보호가 강제되므로 새 기기에서 실제 시스템 동의·거부·철회를 시험해야 한다. 기존 기기의 승인 상태는 새 설치 성공의 근거가 아니다. [Android 로컬 네트워크 권한](https://developer.android.com/privacy-and-security/local-network-permission).

업무 프로필은 개인 앱/데이터와 분리되며 프로필 간 Intent와 URI 접근은 제한될 수 있다. 내부 배포라는 이유로 교차 프로필 권한을 얻는 것은 아니다. [Android Enterprise 개발 지침](https://developer.android.com/work/guide.html).

Android는 버전 정보를 이용해 다운그레이드를 방지한다. 정상 상태 복구는 앱 삭제/데이터 초기화가 아닌 동일 서명의 더 높은 버전에서 이전 동작을 복원하는 방식으로 검증해야 한다. 이는 이 저장소의 현재 anti-rollback 검증과도 맞는다. [Android 앱 버전 관리](https://developer.android.com/studio/publish/versioning).

## 이번 감사 담당의 실행 경계

소스 읽기·정적 경로 검토와 위 P0 보완 파일 작성을 수행했다. `PcTextAuthorityTest`3개와 `PcTextAuthorityDeviceValidation#engineChoiceChangesRevokeCapturedAuthorityAndNoOpPreservesIt`를 추가했다. 폰 회귀는 분리된 파일/환경설정 Context에서만 선택 전환을 시험하고 소유자의 실제 cloud 선택은 바꾸지 않는다. 실제 엔진에는 불일치 revision을 주어 네트워크 preflight 전에 거부하는지 확인한다. 따라서 실제 cloud 비용·전송을 발생시키는 검사는 아니다. 이 담당은 Gradle, ADB, 모델 호출, 설치 또는 실제 사용자 자료 변경을 실행하지 않았다. 최종 통합 APK/기기 결과는 루트가 실제 실행 뒤 추가해야 한다.
