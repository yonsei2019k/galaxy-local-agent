# Product requirements and current boundaries

- 공공기관 업무는 정부24, 국세·지방세, 자동차검사, 교통 과태료·범칙금, 형사 벌과금부터 연결한다. 공식 조회·신청·발급·예약·납부·증빙 재조회 경로를 업무별로 검증한다. 본인 인증은 휴대폰에서 처리하고, 납부는 대상과 금액의 승인 및 결과 재확인을 따른다.

- 국내 맛집·여행·쇼핑 및 예약·구매 요청은 분야에 맞는 네이버·쿠팡과 실행 가능한 공식 MCP/API 연결을 우선 사용한다. 동일 상품·서비스는 플랫폼별 필수 비용과 적용 가능한 할인을 포함한 실제 총액을 기본 비교하고, 구매·예약 가능한 확인 범위의 최저가와 기준 플랫폼 대비 예상 절약액을 대화에 표시한다. 관련 예약·구매 플랫폼과 업체 공식 직판을 분야별로 추가하며, 검색부터 동일 조건 가격 비교, 재고 확인, 예약·주문 준비, 인증, 승인된 결제, 예약번호·영수증 재조회까지 같은 작업에서 지원하는 것을 목표로 한다. 플랫폼별 실제로 검증된 단계는 화면에 표시한다. 실제 결제 후에는 영수증과 확인한 기준가를 대조한다. 자세한 기준은 [국내 거래 검색과 절약액 계획](smartphone-infrastructure-mobilerun.ko.md#국내-예약구매-기본-검색과-절약액-표시)을 따른다.

- Ordinary conversation and agent work use the authorized cloud agent. A current cloud grant that includes personal data permits it in new request text and in the results of tools the current run is authorized to use. The previous grant keeps its original scope. Keep image work, local speech transcription, and the explicit local model available. Explicit local selection binds that request locally. Preserve captured queue permissions, project and branch access, and owner control over protected login, payment and system confirmation.

- 2026-11-01 optional personal briefing: the owner explicitly approved sending the full context of permitted material to Codex for incremental schedule/work analysis. This separately authorized workflow uses the existing Codex login and keeps its own source permissions. New-content detection is deterministic; only actual new batches invoke the existing Codex login. Phone result persistence/readback precedes source ACK. Known-complete new appointments may use the selected calendar; ambiguous, partial, changed, cancelled or conflicting items require phone review. Source-specific permissions and existing messenger read switches remain effective. Messages, files and invitations are never sent by this workflow. See docs/incremental-personal-briefing.ko.md for actual source coverage, batching and developer-connection limits.

- 2026-11-01 owner-approved image recovery exception: explicitly checkpoint-enabled paired-PC requests may retain encrypted original inputs/reference/latent/unreceived PNG for up to 24 hours, bounded to four jobs. Original owner, request, model and runtime bindings must survive resume; cancellation discards that job, transport loss preserves recoverable work, and phone file/metadata verification precedes ACK. Legacy RAM-only requests retain their previous restrictions. Explicit PC image selection never silently changes to phone computation. Generative-video recovery is not implemented by the image worker.

- The phone owns requests, conversations, memories, actions and final files. Private local inference uses the existing phone or paired-PC selection and its captured authorization. Ordinary conversation uses the authorized cloud agent. Necessary text/reference inputs may use the authorized paired-PC path; separately approved encrypted briefing/image retention follows its own limits. Runtimes/weights remain outside Git/APK. Private local processing requires no cloud inference or paid API key. Tailscale uses the same pairing identity/certificate pin; connectivity is not an extra data or tool permission. Network also supports explicit model/package downloads, update checks and public extension discovery.
- The conversation is the primary workflow. Planning, explicit persistent goals, skills, tool use and verification belong inside it; users do not need to select a work-category tab before a normal request. Follow docs/conversation-workflow.ko.md. The model interprets current requests and recent context; deterministic code checks tools, permissions, scope, cancellation and evidence. Keep context bounded and one large model loaded. Benchmark E2B first; select one E4B/Qwen4B quality model after real measurements rather than default-installing three.
- Built-in skills: spreadsheet (CSV/XLSX), document (TXT/Markdown/DOCX), PDF, selected email summarization/reply drafting. Provide Android implementations; desktop Codex skill instructions alone are not an executable phone implementation.
- Default email access is user-shared content/files and drafts through Android Intents. The owner requested actual Gmail replies: the connected Gmail account may send one exact message only after an account/recipient/full-body review; no background worker sends mail or retries an uncertain delivery. Naver/company mail remain separate unverified integrations.
- The owner confirmed Samsung Phone automatic call recording is enabled and requested post-call local transcription and follow-up reports. Process new files only in the specifically selected call-recording folder, preserve originals/raw transcripts, checkpoint bounded work, show partial coverage and source citations, and require review of names/dates/negation/corrections/recipients before external actions. Recognition completion is not accuracy proof.
- Background learning means local analysis of usage/corrections and approved memory, not continuous model-weight training. Run under charging/idle/thermal constraints and release the model afterward.
- User opted into optional system app-usage durations via Android Usage Access. Later explicitly requested Meditong Link, KakaoTalk and Telegram notification receipt/replies and direct screen controls. Provide separate per-app switches and system grants; no silent collection from disabled apps. Notification bodies stay in a bounded session inbox; deterministic, scoped reply rules are separately configured.
- Recommend extensions by ranking a public catalog locally against private task statistics. Never send personal histories, app usage, document contents or memories to GitHub search.
- Every external installation/update must verify source, format, integrity/signature, permissions, network access and compatibility. Unsupported executable/native packages fail closed. Static checks do not guarantee absence of malicious behavior.
- Trusted signed channel updates within existing permissions may apply automatically. New permissions, new publishers or unverifiable packages require review.
- Android display name: 집순이; premium readable native UI, adaptive icon and restrained system-respecting motion. Preserve installed package/signing identity.

Implementation status is tracked in PROJECT_STATE.md. This requirement list does not claim the features are complete.
