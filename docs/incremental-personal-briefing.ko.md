# 연결 후 새 개인 자료 분석

2026-11-01 사용자는 허용한 자료의 전체 문맥을 Codex에 전달하는 것을 명시 승인했다. 이는 기존 일상 로컬 추론과 별개의 선택 기능이다. 처음 등록한 30분 heartbeat는 사용자 토큰 비용 지적 후 PAUSED로 변경했다. 주기적인 Codex 호출은 사용하지 않는다. 연결·미분석 건수 확인은 LLM 없는 로컬 감시가 담당하고, 실제 신규 자료가 있는 경우에만 분석을 실행하는 구조로 준비한다. 현재 이 감시 및 자동 전달 경로는 설치·검증 전이며 동작 중이라고 표현하지 않는다. 다른 채팅·하위 에이전트를 사용하지 않는다.

## 동기화 계약

휴대폰이 자료와 원본별 처리 상태를 소유한다. 식별자와 본문 버전이 같은 자료를 반복 분석하지 않는다. 단순 마지막 실행시각만 올려 누락된 과거 자료를 건너뛰지 않는다. 분석 결과를 앱에 저장하고 재조회한 다음에만 원본 버전을 처리 완료로 기록한다. 저장 실패·연결 해제·취소는 미분석 상태를 유지한다. 이미 분석한 자료의 요약은 새 자료의 문맥으로 참고할 수 있다. 수정·취소·기한 변경은 새 버전으로 처리한다.

문자 본문, 통화기록, 녹음 전사, 알림, 이메일 원문은 서로 다른 자료다. 통화기록으로 통화 내용을 추론하지 않는다. 카카오·메디통·메일 알림은 앱 전체 대화나 메일함과 같지 않다. 알림이 꺼진 방, 잘린 본문, 첨부, 과거 대화는 미확보로 표시한다. 업무 프로필과 보호된 앱 경계를 우회하지 않는다. 기존 자료별 시스템·앱 권한을 유지한다.

## 일정·업무 판단

새 자료와 관련 문맥에서 행사, 참석 주체, 날짜·시간·장소, 서류명, 제출처, 제출 방법, 마감과 준비 작업을 구분한다. 상대 날짜는 자료 원시각과 Asia/Seoul을 기준으로 해석하고 정정·취소·부정 표현을 먼저 반영한다. 원문에 없는 시각·행사명·제출처를 확정값으로 꾸미지 않는다. 근거 인용, 출처 버전, 불명확한 항목을 함께 앱에 전달한다. 불확실하거나 충돌한 항목은 확인 대기로 둔다. 기존 일정 수정·삭제, 참석자 초대, 메시지 발송, 서류 제출은 자동 실행하지 않는다. 확정된 개인 일정의 자동 등록은 실제 쓰기 권한과 목적 캘린더가 확인된 경우에만 한다.

## 구현과 운영

1035 설치본에 암호화 누적함, 앱 보고·일정 검토 화면, 결과 알림, 수정 폼과 날짜·시간 선택기, 홈 위젯 제공자가 연결됐다. 과거 누적 자료가 새 도착 자료를 밀어내지 않도록 최근 행을 먼저 수집하고 최신 시각 순으로 선택한다. 실자료60개 원문 버전의 저장·재조회·완료 처리를2회 Codex 분석으로 확인했다. 이는 전체 자료의 의미 정확도 검증을 뜻하지 않는다. 최종 설치 해시와 구체적인 검증 범위는 PROJECT_STATE/device-validation/agent-change-log를 확인한다.

PC의 일반 프로그램이 60초마다 Codex 실행 여부와 원래 승인한 폰의 연결·새 자료를 검사한다. 이 검사에는 LLM을 사용하지 않는다. 연결 주소가 바뀌면 이미 페어링한 무선 ADB를 탐색하되 원래 단말의 비공개 식별 해시가 일치해야 한다. 다른 폰으로 전환하지 않는다. 공개 네트워크 API를 열지 않으며 앱의 개발 연결 제공자는 DUMP 권한과 shell UID를 모두 요구한다. 일반 배포용 범용 동기화 프로토콜을 완성했다는 뜻은 아니다.

실제 분석은 기존 Codex 로그인으로 실행하는 일회성 비대화형 작업이다. 다른 채팅을 읽거나 메시지를 보내지 않는다. 도구·셸·브라우저·플러그인·메모리·하위 에이전트 기능을 끄고 자료만 구조화한다. 별도 유료 API 키를 설정하지 않는다. 원문은 명령이 아닌 인용 데이터이며, 결과의 원문 버전·정확한 인용·필드·권한을 폰에서 다시 검사한다. 기본 최소 간격 1시간/하루 최대4회이며 실패 시도도 한도에 포함해 재시도 폭주를 막는다. 배치는 최대48건/원문48KB 이내다. 단순 점검이나 재전달에는 모델을 호출하지 않는다.

첫 SMS/통화기록 조회는 기능을 켠 시점의 최근30일부터 시작한다. 문자 원문과 통화 메타데이터를 구분하고, 통화 내용을 통화기록에서 만들어내지 않는다. 메신저·메일은 허용된 앱의 실제 수신 알림 범위다. 카톡·메디통 등 기존 앱별 읽기 스위치를 수집과 전달 양쪽에서 검사한다. 새 알림 저장은 최대64개 대기 작업으로 화면 처리와 분리하고 보관 실패 이력을 표시한다. 미분석 보관은1000건, 처리 버전 이력은20000건으로 제한하며 가득 찬 자료를 완료라고 넘기지 않는다.

폰이 최종 결과를 저장하고 재조회하기 전에는 처리 완료로 올리지 않는다. 결과 노트는 보호된 `codex-briefings` 모음에, 일정 검토 상태와 설정은 별도 암호화 저장소에 둔다. 등록은 선택된 목적 캘린더만 사용한다. 첫 설정에서는 유일한 Google 기본 캘린더 또는 유일한 쓰기 가능 캘린더만 선택할 수 있으며 여러 기본값이면 폰에서 선택한다. 읽기·쓰기 권한, 미래의 유효한 시작/종료, 본인 관련성, 원문 인용, 완전한 자료, 정정/취소와 기존 일정 충돌 여부를 검사한다. 원문에 종료 시각이 없으면 임의 길이를 만들어 확정하지 않는다. 확인 대기는 폰 알림의 확인·수정에서 날짜 선택기와 시각 선택기로 수정 후 저장하거나 등록하지 않을 수 있다. 실제 일정 ID 재조회와 출처 표식으로 중복을 확인한다. 등록은 로컬 캘린더 제공자 확인이며 Google 서버 동기화까지 검증한 것은 아니다.

PC 전송 중 끊기면 결과를 현재 Windows 사용자 DPAPI로 암호화해 재전달하며 추가 모델 호출을 하지 않는다. 결과 캐시는24시간 한도이고 폰에서 기능을 중지하면 폐기한다. 원본 미분석 자료는 폰에 남으며 전송 실패나 캐시 만료만으로 처리 완료가 되지 않는다. 최초 30분 Codex heartbeat는 계속 PAUSED다. Windows 시작 프로그램에는 LLM 없는 감시 프로그램만 등록한다. 폰에서 수집을 끄면 새 전달과 등록을 막는다. 기존 로컬 일상 추론 설정을 이 기능으로 변경하지 않는다.

위젯은 사용자가 Android 홈 화면에 추가하는 제공자이며 자동 배치하지 않는다. 이미 받은 보고·검토함·등록 일정은 PC나 Codex를 열지 않아도 폰에서 확인할 수 있다. 새 Codex 분석에는 PC와 Codex 로그인 및 승인된 연결이 필요하다. 전체 메일함, 닫힌 대화방의 과거 전체 이력, 새 기능을 통한 녹음 전체 전사·사용 패턴 수집은 이번 연결의 완료 범위가 아니다.

## 휴대폰 새벽 기억 정리

기억 메뉴의 새벽 정리를 별도로 켜면 한국 시간 03:00–09:00 안에서 충전·대기 조건이 맞을 때 처리한다. WorkManager가 늦추거나 밤새 조건이 맞지 않으면 다음 실행 때 이어서 처리한다. 기존 자동 기억 정리 설정만으로는 문자 원문이나 카톡 새벽 수집을 켜지 않는다.

문자는 Android 권한으로 읽을 수 있는 SMS 제공자를 과거 항목부터 한정된 페이지로 조회하고, 처리 상태를 남긴다. MMS와 다른 문자 앱의 비공개 저장소는 범위에 포함되지 않는다. 카카오톡은 허용한 수신 알림의 관찰 주제와 직접 가져온 대화를 사용한다. 전사는 집합에 저장된 녹음 전사를 대상으로 한다. 카카오의 과거 전체 대화나 아직 전사하지 않은 녹음을 모두 처리했다는 뜻은 아니다.

기억은 암호화된 로컬 데이터베이스에 출처와 함께 기록한다. 텍스트 파일을 만들거나 백그라운드에서 클라우드 추론을 호출하지 않는다. 이번 자동 정리는 연결한 자료의 주제 관찰을 색인하는 단계다. 출처의 발화자를 사용자로 확정하거나 자유 서술형 모델 요약을 기존 사실로 대체하지 않는다.
