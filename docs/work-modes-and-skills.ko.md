# 한 대화에서 계획·목표·스킬 쓰기

작업 종류를 먼저 선택할 필요 없이 대화창에 원하는 결과와 조건을 입력합니다. 같은 대화에서 자료를 확인하고 계획을 세운 뒤 실행·검증까지 이어가는 흐름입니다. 후속 메시지로 조건을 고치거나 진행 방향을 바꿀 수 있습니다. 계획·목표·스킬을 고르는 상단 모드 메뉴는 기본 채팅에서 사용하지 않습니다.

계획만 필요한지 실행까지 원하는지도 문장으로 설명할 수 있습니다. 예를 들어 “먼저 비교하고 적절한 안으로 문서를 만들어줘”와 “계획만 알려주고 저장하지 마”는 서로 다른 요청입니다. 특정 문구를 맞춰 입력할 필요는 없습니다. 자연어의 뜻과 최근 대화는 모델이 해석하며, 실제 도구 사용은 권한·대상 범위·승인·취소와 실행 결과 검사를 따릅니다. 모든 변형 문장을 정확히 이해한다는 보장은 아닙니다.

모델·계정 연결·권한·자료 선택·프로젝트 설정 등 관리 화면은 그대로 사용할 수 있습니다. 입력창의 **+ → 스킬 찾아보기**는 지침을 참고하는 선택 기능입니다. 현재 방에 저장된 목표가 있으면 같은 메뉴의 **대화의 목표 보기**로 초안과 진행 상태를 확인할 수 있습니다. 이 메뉴를 열었다고 요청이 전송되거나 목표가 생기지는 않습니다.

## 이번 요청에만 적용하는 명령

일반 대화에 명령은 필요하지 않습니다. 범위를 명시하고 싶을 때 아래 명령 뒤에 요청을 함께 입력할 수 있습니다. 다음 일반 메시지에는 그 선택이 남지 않으며 방 전체의 숨은 모드를 바꾸지 않습니다.

| 명령 | 해당 요청의 범위 |
| --- | --- |
| `/act` | 일반 요청과 같은 실행 경로입니다. 허용된 도구로 작업하고 결과를 확인합니다. |
| `/plan` | 허용된 로컬·계정 자료를 읽고 단계·확인 기준을 정리합니다. 원본 변경과 공개 검색은 하지 않습니다. |
| `/goal` | 같은 대화에서 지속 목표를 관리하겠다는 의사를 명시합니다. 새 목표의 내용이나 기존 목표를 어떻게 관리할지 함께 적습니다. 과거의 읽기 전용 목표 모드를 선택하는 명령이 아닙니다. |
| `/debug` | 증상·원인 가설·승인된 수정·검증을 요청합니다. 실제로 제공된 도구 범위만 사용합니다. |
| `/review` | 허용된 자료를 읽어 문제와 개선안을 검토합니다. 원본 변경과 공개 검색은 하지 않습니다. |
| `/research` | 공개 자료만 조사합니다. 개인 기억·계정·과거 대화·프로젝트 지침·첨부는 자동 제공하지 않습니다. |

요청 내용 없이 분류 명령만 입력해도 다음 메시지의 방식을 미리 설정하지 않습니다. `/goal`은 목표 관리 요청으로 대화에 전달되며 필요한 목표 내용은 대화로 확인할 수 있습니다. 파일 저장·재조회와 실제 컴파일·테스트 통과는 구분합니다. 현재 등록 도구에는 일반 셸·Gradle·Git 실행기가 없습니다.

## 필요한 경우에만 지속 목표 관리

일반 작업마다 목표를 만들 필요는 없습니다. 여러 차례 이어갈 일을 목표로 보관하고 싶을 때 원하는 결과·완료 기준·조건을 대화로 요청합니다. 목표는 방마다 하나를 암호화된 DB에 저장하며 앱 재시작 뒤에도 읽을 수 있습니다. 예를 들어 목표를 저장하고, 기준을 수정하고, 실행을 시작하거나 일시 정지하는 요청을 같은 대화에서 이어갈 수 있습니다.

실제 기능은 다음 도구에 연결됩니다. 도구의 존재나 모델의 제안만으로 사용자가 목표 관리에 동의한 것으로 보지 않습니다.

| 도구 | 실제 동작과 한계 |
| --- | --- |
| `get_goal` | 현재 방의 목표와 완료 기준 페이지를 읽습니다. 전체 접근 범위와 실제 목표·버전을 확인합니다. |
| `create_goal` | 명시한 요청으로 새 초안을 저장합니다. 일반 작업의 부수 효과로 목표를 만들거나 실행을 시작하지 않습니다. |
| `update_goal` | 읽은 목표·버전을 기준으로 내용을 수정합니다. 지정하지 않은 완료 기준은 보존합니다. 작업이 바뀌면 이전 연결 실행을 정리하고 관련 검증 상태를 초기화합니다. 동일한 내용은 기존 근거를 보존합니다. |
| `start_goal` | 저장된 목표를 한 번의 제한된 실행으로 대기열에 넣습니다. 목표 저장과 실행 시작은 구분됩니다. |
| `pause_goal` | 연결된 목표 실행을 정리하고 일시 정지합니다. 호출한 실행을 나중에 중단해야 하는 경우에는 준비 상태로 표시합니다. |
| `resume_goal` | 일시 정지한 목표에 한 번의 실행을 다시 연결합니다. 같은 작업·범위의 실제 검증 근거만 재사용합니다. |
| `clear_goal` | 명시 요청과 별도 확인 후 연결 실행을 정리하고 저장 목표를 해제합니다. 대화 기록과 이미 수행한 외부 작업은 지우지 않습니다. |

목표 시작·재개는 주기 실행이나 무제한 자율 실행을 예약하지 않으며 새로운 계정·파일·도구 권한도 주지 않습니다. 대기열 저장, 일시 정지 준비, 목표 지침 읽기는 업무 완료의 근거가 아닙니다. 실제 중단이 뒤로 미뤄지면 `PREPARED`로 구분하고 중단 완료라고 주장하지 않습니다.

각 기준은 미확인·실패·실행 기록으로 검증됨·사용자 직접 확인을 구분합니다. 사용자가 체크하는 것은 **직접 확인**이며 자동 검증으로 바뀌지 않습니다. 모든 기준을 확인해도 전체 목표를 자동 완료 처리하지 않습니다. **대화의 목표 보기**에서 내용을 직접 편집하거나 상태를 확인할 수 있습니다. 다른 작업이 목표를 바꾸면 작성 중인 내용을 유지하고 최신 상태를 다시 읽도록 안내합니다.

대기 중인 목표 요청은 당시 목표와 조건을 고정해 보존합니다. 대기열에서 본문만 바꿔 목표 조건을 우회하지 않습니다. 목표 수정·해제는 연결된 기존 실행의 정리와 실제 저장 버전 검사를 거칩니다. 대화 내용을 비우거나 방을 삭제하면 방 목표도 삭제합니다. 프로젝트를 옮기면 목표 내용은 유지하고 새 범위에서 완료 기준을 다시 확인합니다. 이미 생성한 외부 파일·일정과 과거 실행 기록은 별도로 유지됩니다.

## 스킬은 필요할 때 읽는 지침

모델은 대화의 작업에 필요한 지침을 `list_skills`로 찾고 `read_skill`로 읽을 수 있습니다. 사용자가 라이브러리를 먼저 열거나 스킬 이름을 선택할 필요는 없습니다. **+ → 스킬 찾아보기**에서는 현재 소스 번들 24개 지침의 본문·출처·관련 도구·실행 한계를 읽을 수 있습니다.

- 계획, 목표 설정, 디버그, 코드 검토, Android 코딩, 완료 전 검증
- 문서, 스프레드시트, PDF, 이메일, 일정, 메모·기억, 파일 관리
- 웹 조사, 쇼핑 비교, 이미지 작업, 보안 점검, 확장 검토
- 업무 브리핑, 가능한 시간 계산, 논문·인용 조사, 메시지 분석, 녹음 분석, 근거 종합

선택한 본문은 SHA-256을 확인하고 원문 전체를 사용합니다. 문맥에 들어가지 않으면 이전 선택 지침을 제외하거나 명시적으로 중단하며 조용히 잘라 넣지 않습니다. 지침 조회는 실제 작업의 실행 증거로 계산하지 않습니다. GGUF는 실제 토큰 측정을 지원하며, 선택 본문에 필요한 사전 측정을 제공하지 않는 LiteRT 경로는 해당 한계를 표시합니다.

스킬은 APK에 포함되는 Android용 업무 지침이며 모델 가중치는 고정합니다. 문서·표·PDF는 현재의 기기 내 도구를 이용하고, 계정 서비스는 실제 인증과 연결 상태에 따라 사용합니다. Git·MCP·호스트용 Python/Playwright 프로그램을 설치했다고 표시하지 않습니다. 외부 지침이나 인용 자료만으로 실행 도구·목표 관리 의사·접근 권한이 추가되지 않습니다.

공식 사용 빈도 순위는 확인되지 않아 순위를 붙이지 않았습니다. [출처·라이선스·Android 이식 범위](mobile-skills-provenance.ko.md), [번들 목록](../app/src/main/assets/skills/catalog.json)을 참고하세요.

## 구버전 요청의 범위 보존

새 일반 요청은 예전에 방에 저장된 모드와 관계없이 기본 대화 경로를 사용합니다. 다만 **이미 저장된 큐 요청과 답변 이어쓰기의 `mode`·`allowTools` 값은 제출 당시 그대로 보존**합니다. 새 입력 정책으로 다시 해석해 읽기 전용 요청을 쓰기 가능 요청으로 바꾸거나, `allowTools=false`인 이어쓰기에 도구 권한을 추가하지 않습니다.

따라서 구형 PLAN/GOAL/REVIEW 요청의 읽기 전용 경계와 RESEARCH의 개인 자료 배제는 유지합니다. 신규 `/goal` 관리 요청은 일반 실행 경로에서 목표 전용 도구를 사용하며 구형 읽기 전용 GOAL 요청과 구분합니다. 레거시 `RunModeSelector` 컴포넌트와 그 합성 검사는 호환 계약을 위해 남아 있지만 기본 채팅 화면에서는 사용하지 않습니다.

## 검증 상태

이 안내는 현재 소스의 사용 흐름을 설명합니다. 실제 설치본과 기능 통과 여부는 [공유 변경 기록](agent-change-log.md)의 최신 체크포인트를 확인합니다. 소스 저장, JVM 통과, UI 합성 검사, APK 빌드, 설치, 실제 모델의 다중 턴 작업 성공은 각각 구분합니다. 형식·단위 검사 통과가 복잡한 자연어 요청의 일반적인 성공을 보증하지 않습니다.
